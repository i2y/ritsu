## E001 — kaname として読めません

**いつ出るか**: 知らない文字、閉じていない文字列や括弧、タブ、全角の空白、存在しない日付（`2026-02-30`）、単位の表に無い単位、桁区切りのカンマ（`1,000USD`）があるとき。ほかの言語の `==`、`&&`、`||`、`!` と、続けた比べ（`a < b < c`）も kaname の字句にありません。式や型を書くところに、そこで読めない語や記号があるときも出ます。

**直し方**: 示された位置を直してください。等しいかは `=`、等しくないかは `!=` で、「かつ」「または」「でない」は `and`、`or`、`not` で書きます。比べを二つ並べるときは `a < b and b < c` と書き、桁は `_` で区切れます（`1_000USD`）。

**再現**:

```kn
module 例(example) v1

fn 同じか(same)(左(a): number range >=0 <=9, 右(b): number range >=0 <=9) -> bool
  左 == 右
```

## E002 — 予約語は名前にできません

**いつ出るか**: 名前を書くところに、式と文の中で別の意味に読める 13 語（`let` `if` `then` `else` `match` `some` `none` `true` `false` `and` `or` `not` `in`）のどれかを書いたとき。ほかのキーワードは、その位置でしか読まないので名前にできます（`total`、`count`、`description` など）。

**直し方**: 別の名前にしてください。

**再現**:

```kn
module 例(example) v1

fn 三(three)() -> number
  let then = 3
  3
```

## E003 — モジュールの組み立てが違います

**いつ出るか**: 一行目が `module <名前> v1` でないとき、左端の行が決まった順（`module`、`description`、`use`、宣言（`enum`、`record`、`fn`）、`examples`）にないとき、一度だけの行（`module`、`description`、`examples`）を二度書いたとき、左端の行が知らない語で始まるとき、列挙に `default` や `open` を書いたとき、`use` の行の形が違うとき。

**直し方**: モジュールは、`module`、`description`、`use` の行、宣言、`examples` の順に書いてください。`enum`、`record`、`fn` は互いに好きな順に並べられます。

**再現**:

```kn
module 例(example) v1

fn 一(one)() -> number
  1

use module 価格 from "価格.kn"
```

## E005 — 生成するコードに出る名前には、ASCII の別名が要ります

**いつ出るか**: モジュール、関数、引数、レコード、フィールド、列挙、列挙の値の名前が ASCII でなく、別名が無いとき。別名が ASCII の名前（英字か `_` で始まり、英字・数字・`_` だけ）でないときも出ます。`let` の名前と、組み込みの関数に渡す関数の引数には要りません。

**直し方**: 名前のすぐあとに、`請求日(invoiced)` のように丸括弧で別名を付けてください。

**再現**:

```kn

```

## E006 — 同じ名前が二度あります

**いつ出るか**: モジュールの中で、`use` の名前と宣言（`enum`、`record`、`fn`）の名前か別名が重なるとき。一つのレコードのフィールド、一つの関数の引数、一つの列挙の値が重なるときも出ます。関数か `use` に組み込みの関数の名前（`sum`、`map` など）を付けたとき、`let` や `some` の名前がその場でもう名前になっているときも出ます。

**直し方**: どちらかの名前を替えてください。

**再現**:

```kn

  1

fn 見積もる(quote_again)() -> number
  2
```

## E101 — この名前のものはありません

**いつ出るか**: 式の名前、型の名前、関数、規則の出力、レコードのフィールド、列挙の値、日付のファイルの日付が、どれも指すものを持たないとき。列挙の値は、型の決まらないところでは `<列挙>.<値>` と書きます。

## E102 — 型が合いません

**いつ出るか**: 値の型が、渡す先（関数の引数と答え、レコードのフィールド、規則と日付の入力、振替の引数）の型と違うとき。単位と税区分も型で、同じ次元の違う単位（`money[USD]` と `money[USDc]`）や、税込と税抜は合いません。足し引きと比べの両辺、`if` と `match` の答えどうし、リストの要素どうしが合わないときも出ます。

**直し方**: 同じ型にしてください。単位の換算は `fee in USDc` のように書きます（kaname は黙って換算しません）。

**再現**:

```kn
module 例(example) v1

fn 手数料(fee)(金額(amount): money[USD] range >=0USD <=1000USD) -> money[USDc]
  金額
```

## E103 — 丸めた値を受け取るところに、丸めていない値を渡しています

**いつ出るか**: 金額と率の積、量を定数で割った値、値で割った値のような丸めていない値を、関数の引数と答え、レコードのフィールド、規則と日付の入力、振替の引数、`running_totals` の重み（重みは、答えのレコードのフィールドに入ります）に渡したとき。そこが受け取るのは、単位の整数か、率の刻みの上の値です。重みが率なら、その型の刻みのまま受け取るので、丸めていない値になるのは、値で割って刻みが分からなくなったときだけです。`let` には丸めていない値を入れられます。

**直し方**: 丸め方と刻みを書いてください（`half_up(amount * 3%, 1USDc)`）。丸め方は `up`、`down`、`half_up`、`half_down`、`half_even` の五つです。

**再現**:

```kn
module 例(example) v1

fn 手数料(fee)(金額(amount): money[USDc] range >=1USDc <=100_000USDc) -> money[USDc]
  金額 * 3%
```

## E104 — 丸めの刻み、率の刻み、単位の換算が合いません

**いつ出るか**: リテラルが書いた単位の整数でないとき（`0.5USD`、単位の無い `0.4`）、リテラルを読む先の単位で整数にならないとき（`mass[g]` と比べる `1lb`）、`in` で違う通貨や次元に換算しようとしたとき、率の刻みや丸めの刻みが正の値でないとき、範囲の端や値が率の刻みの上にないとき。

**直し方**: 小さな単位で書くか（`50USDc`）、割合なら率で書いてください（`40%`）。違う通貨のあいだに為替の率は無いので、換算は表に書いてください。

**再現**:

```kn
module 例(example) v1

fn 手数料(fee)(金額(amount): money[USD] range >=0USD <=1000USD) -> money[GBP]
  金額 in GBP
```

## E105 — その型にない演算です

**いつ出るか**: 型が持たない演算を書いたとき。日付の足し算（`paid_on + 30`。kaname が日付でできるのは二つの日付の差だけ）、金額どうしや重さと長さの掛け算、文字列の大小の比べや `+`、順序の無い列挙の大小、値が無いことがある値の算術と比べ、値を呼ぶこと、`match` で数を分けることなど。

**直し方**: 日付の足し算は koyomi に書いて、その日付の関数を呼んでください。値が無いことがある値は `match` で分け、文字列は `concat` でつなぎます。

**再現**:

```kn
module 例(example) v1

fn 期日(due)(請求日(invoiced): date range >=2026-01-01 <=2026-12-31) -> date
  請求日 + 30
```

## E106 — `match` が取りこぼす値があります

**いつ出るか**: `match` の分岐が、列挙の値、`true` と `false`、`none` と `some x` のどれかを受けないとき。上の分岐がもう受けた値を、下の分岐にもう一度書いたときも出ます。

**直し方**: 受けない値の分岐を足すか、重なった値を一つの分岐にまとめてください。

**再現**:

```kn
module 例(example) v1

enum 区分(tier) = 一般(basic) | 銀(silver) | 金(gold)

fn 点数(points)(区分(t): 区分) -> number
  match 区分
    一般 => 1
    銀 => 2
```

## E107 — 呼び出しの引数が合いません

**いつ出るか**: 関数、規則、日付の呼び出しで、引数が足りないとき、取らない引数を渡したとき、同じ引数を二度書いたとき、名前を付けずに渡したとき。組み込みの関数に名前を付けた引数を渡したとき、引数の数が違うとき、レコードを作るのにフィールドが足りないか二度書いたとき、関数や規則を呼ばずに値として書いたときも出ます。

**直し方**: 引数を全部、名前を付けて一度ずつ書いてください（`charges(debt: d, days_late: n)`）。組み込みの関数には名前を付けずに順に渡します。

**再現**:

```kn
module 例(example) v1

fn 倍(double)(数(n): number range >=0 <=9) -> number
  数 * 2

fn 四(four)() -> number
  倍()
```

## E108 — 宣言が足りないか、成り立ちません

**いつ出るか**: 数と日付の引数に範囲（`range`）が無いとき、リストの引数に要素の数の上限（`count`）が無いとき、率の引数に刻み（`rate[step 0.01%]`）が無いとき。引数の型から（リスト、オプショナル、ほかのレコードを通して）届くレコードのフィールドにも要ります。答えにだけ使うレコードのフィールドは範囲を省けます。率の刻みは、関数の答えとどのレコードのフィールドにも要ります（省けるのは `let` だけです）。範囲に値が一つも無いとき、端を二度書いたとき、数と日付でないものに `range` を、リストでないものに `count` を書いたとき、レコードが自分自身を含むときも出ます。

**直し方**: 範囲を書いてください（`qty : number range >=1 <=20`、`lines : list[Line] count >=1 <=30`）。範囲はホストとの約束で、生成したコードは入口でそれを確かめます。

**再現**:

```kn
module 例(example) v1

fn 倍(double)(数(n): number) -> number
  数 * 2
```

## E109 — 組み込みの関数の使い方が違います

**いつ出るか**: 組み込みの関数の引数でないところに関数（`x => …`）を書いたとき、組み込みの関数が関数を取る引数に関数でないものを渡したとき、その関数の引数の数が違うとき、`text` に率や丸めていない値を渡したとき、`mod` の割る数が正の整数の定数でないとき、組み込みの関数を呼ばずに値として書いたとき。

**直し方**: 関数は `sum(xs, x => …)` のように組み込みの関数に渡すときだけ書き、ほかで使う計算は `fn` で名前を付けてください。

**再現**:

```kn

fn 一(one)() -> number
  let 倍 = x => x * 2
  1
```

## E111 — ブロックに答えがありません

**いつ出るか**: ブロックの最後の行が値を表す式でないとき（`let` で終わる、本体が無い）、`if` に `else` が無いとき、ブロックの答えのあとにまだ行があるとき、`if`、`else`、`match` の分岐、`let x =` の下にブロックが無いとき。

## E201 — 読むファイルを読めません

**いつ出るか**: `use` で読むファイルが無いとき、拡張子が種類に合わないとき（`use rule` は `.rule`、`use dates` は `.cal`、`use book` は `.book`、`use module` は `.kn`）、その言語の検査を通らないとき（rulec、koyomi、chobo、kaname が言うことを注に挙げます）。

**再現**:

```kn

```

## E203 — モジュールの読み込みが輪になっています

**いつ出るか**: `use module` でたどると、読んでいるモジュールに戻ってくるとき。輪の中のモジュールは、どれもこのコードを出します。

## E204 — 振替の呼び出しが、帳簿に合いません

**いつ出るか**: 帳簿に無い振替や操作を書いたとき（すぐに確定する振替の操作は `do`、仮押さえする振替の操作は `hold`、`post`、`void`）、振替の引数が足りないとき、取らない引数を渡したとき、一部を確定する `post` で額の引数の一部だけを書いたとき。

**直し方**: 帳簿の振替と操作を、`<帳簿>.<振替>.<操作>(<引数>: …)` の形で書いてください。`do` と `hold` は引数を全部、`post` と `void` はキーの引数を書きます。

**再現**:

```kn
module 例(example) v1

use book 台帳 from "台帳.book"

fn 受ける(take)(支払い(payment): string, 売り手(seller): string, 金額(amount): money[USDc] range >=1USDc <=100_000USDc) -> 台帳.入金.do
  台帳.入金.hold(支払い: 支払い, 売り手: 売り手, 金額: 金額)
```

`台帳.book`:

```

account 売り手の残高(売り手: string) : USD

```

## E301 — 値が、渡す先の範囲の外になることがあります

**いつ出るか**: 規則の入力（数の入力と、値で範囲を書いた順序のある列挙の入力）、日付の整数の入力、関数の引数と答え、レコードのフィールド、`isqrt` の引数に渡す値が、その範囲の外になる、関数の実際の入力を見つけたとき。注に、その入力と、そのとき渡る値を書きます。`check` は、範囲の解析が収まると示せない場所についてだけ、関数のベクタを流して例を探します。

**直し方**: 渡す前に `if` か `match` でその範囲に狭めるか、渡す先の範囲を広げてください。

**再現**:

```kn
module 例(example) v1

fn 請求(charge)(日数(days): number range >=1 <=30) -> number
  日数

fn 遅れ(late)(支払日(paid): date range >=2026-01-01 <=2026-12-31, 期日(due): date range >=2026-01-01 <=2026-12-31) -> number
  請求(日数: 支払日 - 期日)
```

## W301 — 値が渡す先の範囲に収まるかを決められません

**いつ出るか**: 範囲の解析が、渡す値が範囲に収まると示せず、関数のベクタにも範囲の外にする入力が無かったとき。生成したコードが、走らせたときにその場所で確かめます。範囲の解析は区間で数えるので、同じ値が二度出る式（`side * (10 - side)`）や、再帰の答えは、本当より広く見積もります。

**直し方**: `if` か `match` で範囲に狭めると、範囲の解析がそれを読んで示せるようになります。

**再現**:

```kn
module 例(example) v1

fn 面積(area)(辺(side): number range >=1 <=8) -> number range >=0 <=24
  辺 * (10 - 辺)
```

## W302 — 途中の値が int64 に収まるかを決められません

**いつ出るか**: 範囲の解析が、途中の値が int64 に収まると示せず、関数のベクタにも超える入力が無かったとき。範囲の解析は、範囲を書かない再帰の答えを、どの値にもなりうるものとして数えます。生成したコードが、走らせたときに確かめます。

**直し方**: 入力の範囲を狭めるか、先に丸めてください。再帰の関数には、答えの範囲を書いてください。

**再現**:

```kn
module 例(example) v1

fn 段数(steps)(数(n): number range >=0 <=100) -> number
  if 数 <= 0 then 0 else 段数(数: 数 - 1) + 1
```

## E303 — 割る数が 0 になることがあります

**いつ出るか**: 割る数（`allocate` の三つ目の引数も）が 0 になる、関数の実際の入力を見つけたとき。注に、その入力を書きます。

**直し方**: 割る前に `if` で 0 を除くか、割る数の範囲から 0 を外してください。

**再現**:

```kn
module 例(example) v1

fn 一人分(each)(金額(amount): money[USDc] range >=0USDc <=1_000USDc, 人数(people): number range >=0 <=10) -> money[USDc]
  down(金額 / 人数, 1USDc)
```

## W303 — 割る数が 0 にならないかを決められません

**いつ出るか**: 範囲の解析が、割る数が 0 にならないと示せず、関数のベクタにも 0 にする入力が無かったとき。名前の付いた値を `if` で比べると狭まりますが、二つの式のあいだの関係（`any` が成り立てば `filter` の要素は一つ以上）は読みません。生成したコードが、割る前に確かめます。

**直し方**: 割る数に名前を付け、割る前に `if` で 0 を除いてください。

**再現**:

```kn
module 例(example) v1

record 明細(Line)
  金額(amount) : money[USDc]  range >=0USDc <=1_000USDc
  メディア(media) : bool

fn メディアの平均(media_average)(明細(lines): list[明細] count >=0 <=10) -> money[USDc]?
  if any(明細, 一件 => 一件.メディア)
    down(sum(明細, 一件 => 一件.金額) / count(filter(明細, 一件 => 一件.メディア)), 1USDc)
  else
    none
```

## E401 — 関数のエフェクトが、書いたエフェクトに収まりません

**いつ出るか**: `total` と書いた関数に、実行時に失敗しうる場所か、輪になる呼び出し（再帰）があるとき。`fails` に書いていない種類の失敗が起きうるとき、`diverges` と書かずに再帰があるときも出ます。呼んだ関数のエフェクトも、呼んだ側のエフェクトに入ります。言語をまたぐ判定（ritsu の X2・X3・X4・X6）が決める場所は、その答えで数えます。示せなかった場所と例のある場所は、ほかの場所と同じく、実行時に失敗しうる場所です。答えを受け取らない実行では、その場所は答えを待つ場所で、この確かめに使いません。

**直し方**: 注に挙げた場所を示せるようにする（範囲を狭める分岐を書く）か、書いたエフェクトを広げてください。再帰する関数には `diverges` と書きます。

**再現**:

```kn
module 例(example) v1

fn 段数(steps)(数(n): number range >=0 <=100) -> number range >=0 <=100 total
  if 数 <= 0 then 0 else min(段数(数: 数 - 1) + 1, 100)
```

## W501 — 表に書くべき判断が、コードにあります

**いつ出るか**: `if` か `match` が、業務の定数（金額、量、率、日付、列挙の値、`true` と `false`、それだけでできたレコード。`match` では数も）を答えにするとき。業務の値と 0 でないしきい値（金額、量、率、日付、数のリテラル）の比べを、`if` の条件と `match` で分ける値のほかで値にするときも出ます。答えが `none` の分岐、`none` と `some x` に分けるだけの `match`、別の列挙の同じ名前の値に対応づけるだけの `match`、0 との比べは、警告になりません。

**直し方**: 判断を rulec の表に書いて、規則を呼んでください。表に書けば、完全性と重なりを rulec が確かめ、承認する人がページで読めます。

**再現**:

```kn
module 例(example) v1

fn 送料(shipping)(合計(total): money[USD] range >=0USD <=10_000USD) -> money[USD]
  if 合計 >= 35USD then 0USD else 5USD
```

## E601 — 例が成り立ちません

**いつ出るか**: `examples` の行の関数を、ホストが呼ぶときと同じように参照インタプリタで流した答えが、書いてある答えと違うとき。書いてある種類で失敗しないとき、引数が関数の範囲の外にあるとき（種類 `input` の失敗）、呼び出しが深すぎて評価が止まらないときも出ます。

**直し方**: 関数か、例に書いた答えのどちらかを直してください。失敗を書くときは `fails range` のように種類を書きます。

**再現**:

```kn
module 例(example) v1

fn 倍(double)(数(n): number range >=0 <=9) -> number
  数 * 2

examples
  倍(数: 2) = 5
```

## E602 — 例の書き方が違います

**いつ出るか**: `examples` の行が、このモジュールの関数の呼び出しでないとき、呼び出しのあとに `= <答え>` も `fails <種類>` も無いとき、答えがその関数の答えの型の値でないとき。

**直し方**: `<関数>(<引数>: <値>, …) = <答え>` か `<関数>(…) fails <種類>` と書いてください。続きは、より深く字下げして次の行に書けます。

**再現**:

```kn
module 例(example) v1

fn 倍(double)(数(n): number range >=0 <=9) -> number
  数 * 2

examples
  倍(数: 2) = true
```

## W901 — 鍵の形の値が書かれています

**いつ出るか**: `.kn` のどこか（文字列でもコメントでも）に、プロバイダーが形を決めている鍵の形の値（AWS のアクセスキー ID、GitHub・Slack・Stripe・OpenAI・Anthropic・Google の鍵やトークン、Slack の Incoming Webhook の URL、PEM の秘密鍵）があるとき。モジュールが読めないときも出ます。診断には鍵の種類と、接頭辞と、長さだけを出し、鍵そのものも、その行も出しません。

**直し方**: 鍵はコードが動くところ（環境変数、プラットフォームの接続やシークレットの置き場）に置き、そこから読んでください。本物の鍵なら、まずプロバイダーで無効にしてください。ファイルから消しても、リポジトリの履歴には残ります。テスト用の値なら、同じ行のコメントに `ritsu: test secret` と書いてください。

**再現**:

```kn
module 地図(maps) v1

# 検証用のサイトの地図の API キー: AIzaSyD-ritsu-fake-key-for-tests-000000
fn 地域(region)(番号(code): string) -> string
  番号
```
