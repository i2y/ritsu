だれが何をできるか

action ごとに、sekisho check が数えた組み合わせを、Cedar の答えと決めたポリシーが同じものどうしでまとめた表です。一つの列だけが違う行は一つにまとめ、その列にはまとめた値を書きます。その列がとるすべての値をまとめたときは「どれでも」、一つを除くすべてのときは「〜以外」と書きます。「-」は、その行には当てはまらない列です（ワークフローの役割など）。

ポリシー

ポリシーごとに、.gate に書いた行と、sekisho gen --target cedar が生成する Cedar を並べます。permit は、当てはまる組み合わせを許します。forbid は、当てはまる組み合わせを拒み、permit も当てはまるときは forbid が勝ちます。どのポリシーも当てはまらない組み合わせは、Cedar が拒みます。規則の答えを比べる条件は、.gate では .rule に書いた値の名前（上限まで）で、Cedar では Cedar に渡す文字列（"within_limit"）で書きます。

permit 職員は注文を見られる（staff_view_orders）

職員はどの注文も見られる

  • 注文を見る では 7 通りを許します。どれも、ほかの permit は許しません。

permit 顧客は自分の注文を見られる（customers_view_their_orders）

お客さまは自分の注文を見られる

  • 注文を見る では 1 通りを許します。ほかの permit は、それを許しません。

permit 係は上限まで返金できる（clerks_refund_within_their_limit）

係は、返金の期間のあいだ、自分の上限まで返金できる

  • 返金する では 36 通りを許します。そのうち 12 通りは、ほかの permit が許しません。

permit 責任者は期間内なら返金できる（managers_refund_in_period）

責任者は、返金の期間のあいだ、どの額でも返金できる

返金の期間が過ぎても、イングランドとウェールズの営業日なら、責任者は返金できる

  • 返金する では 24 通りを許します。どれも、ほかの permit は許しません。

返品のワークフローは、返品済の注文を 50 ポンドまで返金できる

計算した値

action が計算して、Cedar の context に入れる値です。生成したコードが、サービスのデータ、操作の引数、サーバーの時計から計算し、呼ぶ側からは受け取りません。規則と日付のページは、rulec と koyomi が描いた、人が読むページをそのまま載せています。

返金する の 返金の区分（refund_band）

  • 書き方：返金の区分 = 返金の上限(金額: 金額, 上限: principal.返金できる額).区分
  • rulec "rules/返金の上限.rule" output 区分 が、金額 と principal.返金できる額 から計算します。
  • 値：上限まで、上限超え。Cedar に渡す文字列は "within_limit"、"over_limit" です。
  • principal の型が 職員 のときだけ計算します。ほかの型のときは、context にこの値がありません。

返金する の 期間内（in_period）

  • 書き方：期間内 = today <= 返金の期限.最終日(支払日: resource.支払日)
  • today <= koyomi "dates/返金の期限.cal" date 最終日 として計算します。koyomi が resource.支払日 から日付を求め、today がその日かそれより前なら「はい」です。
  • today は、UTC からのオフセットが +00:00 の日付です（today の行）。
  • 値：はい、いいえ（Cedar では true と false）。

返金する の 営業日（business_day）

  • 書き方：営業日 = today is open in 英国
  • today is open in koyomi "calendars/england_and_wales.cal" として計算します。today がそのカレンダーの営業日なら「はい」です。
  • today は、UTC からのオフセットが +00:00 の日付です（today の行）。
  • 値：はい、いいえ（Cedar では true と false）。

期間内 と 営業日 は、どちらも today を読みます。koyomi が宣言した範囲のすべての日で計算すると、値の組 4 通りのどれも起こります。

期待、職務の分離、役割

期待

  • 係は上限を超えて返金しない（返金する で拒むことを期待）：責任者でない係は、自分の上限を超えて返金することがない。この期待が選ぶ 128 通りのすべてで成り立ちます。
  • 返金済の注文は返金しない（返金する で拒むことを期待）：返金済の注文を返金する人はいない。この期待が選ぶ 264 通りのすべてで成り立ちます。
  • 責任者は期間内に返金できる（返金する で許すことを期待）：停止中でなく、監査でもない責任者は、返金の期間のあいだ、返金済でない注文を返金できる。この期待が選ぶ 48 通りのすべてで成り立ちます。

職務の分離

  • 返金と監査を分ける（返金する、返金を書き出す）：返金をする人は、返金を確かめる人ではない。成り立ちます。二つ以上を許される principal はいません。

役割

  • 係（clerk）：お客さまに応対し、少額の返金をする。can に 注文を見る、返金する を並べています。
  • 責任者（manager）：係ができない返金をし、返金の期間が過ぎても営業日なら返金する。係 を含みます。can に 注文を見る、返金する を並べています。
  • 監査（auditor）：あとから返金を確かめる。can に 注文を見る、返金を書き出す を並べています。

役割を一つだけ持つ principal（その役割が含む役割も持つ）が、action を許されるかです。「いつも許す」はほかの値のどの組み合わせでも許すこと、「組み合わせによる」は許す組み合わせと拒む組み合わせの両方があること、「許さない」はどの組み合わせでも拒むことです。「-」は、action がその型の principal を取らないことを表します。役割に can を書くと、いつも許すか組み合わせによる action が can と同じであることを sekisho check が確かめます。

ワークフロー

ワークフローは、自分の資格で操作を呼びます。Cedar では principal Workflow::"<名前>" です。ワークフローごとに、どの action をどれだけ許されるかを並べます。

ワークフロー 返品（returns）

返品された品物が倉庫に戻ったら、その注文を返金する

  • フロー：dandori "flows/returns.flow"
action許されるか
返金する（refund_order）組み合わせによる（32 通りのうち 4 通りを許す）

フローが呼ぶ操作

フローのタスクが呼ぶ操作と、それを守る action、そのワークフローがその action を許されるかです。ritsu check は、これを言語をまたいで確かめます。

守る操作

action が守る契約の操作です。サービスは、操作を行う前に、その action について Cedar に尋ねます。参照のパスはルートからです。
