## E001 — 読めない字句があります

**いつ出るか**: 知らない文字、閉じていない文字列、形の崩れた日付や固定（`sha256:` のあとが 16 桁の小文字の 16 進数でない）、数で始まる英字の名前があるとき。

**直し方**: 示された位置を直してください。文字列は `"…"` で閉じ、日付は `2026-01-01` の形で書いてください。

**再現**:

```cal
dates t v1
description "閉じていない
```

## E002 — この位置に書けない語があります

**いつ出るか**: 行の中で、構文がその語を受け付けないとき。知らない操作、`else` のあとの知らない扱い、`roll` のあとの知らない慣行など。

**直し方**: 注に挙がる書き方のどれかにしてください。

**再現**:

```cal

inputs
  d : date  range >=2026-01-01 <=2026-01-31

date x = d
  next month
```

**直し方**: 休みの決まりなら `calendar 東京の営業日(tokyo) v1`、日付の関数なら `dates 支払条件(payment_terms) v1` のように書き始めてください。

## E302 — 日付が単調ではありません

**いつ出るか**: 隣り合う二日のうち、後の日のほうが早い結果になる組があるとき。`if closed` を使った日付で起きます。

**直し方**: `roll` で書けないかを考えてください。単調でなくてよいなら、条件を消してください。

**再現**:

```cal
dates t v1
use calendar "weekends.cal"

inputs
  d : date  range >=2026-01-01 <=2026-01-31

date x = d
  if closed + 3 days

claims
  遅いほど遅い : x is monotonic
```

`weekends.cal`:

```
calendar 土日(weekends) v1
offset +09:00

closed weekly sat, sun
```

関連: [E301](#e301)

## E303 — 例の値が違います

**いつ出るか**: 例の行に書いた日付が、参照インタプリタの計算と違うとき。例の入力が範囲の外のときも。

**直し方**: 計算を読んで、例か決まりを直してください（直し方に、計算どおりの行が出ます）。

**再現**:

```cal
dates t v1

inputs
  d : date  range >=2026-01-01 <=2026-01-31

date x = d
  + 1 day

examples
| d          | -> x       |
| 2026-01-01 | 2026-01-03 |
```

関連: [E304](#e304)

## E304 — 例に入力か日付の列が足りません

**いつ出るか**: `examples` の表に、入力か日付の列が無いとき。人が書いた値だけが、参照インタプリタと生成したコードに共通の誤りを見つけられます。

**直し方**: 足りない列を足してください（日付の列は `-> <名前>`）。

**再現**:

```cal
dates t v1

inputs
  d : date  range >=2026-01-01 <=2026-01-31

date x = d
  + 1 day

examples
| d          |
| 2026-01-01 |
```

## E305 — 検査の予算を超えました（確かめていません）

**いつ出るか**: 入力の組み合わせの数（日付の範囲の日数と、整数の入力の範囲の大きさの積）が予算を超えるとき。koyomi は、一部の入力だけを試して通すことはしません。

**直し方**: 範囲を狭めるか、ファイルを分けるか、`--budget` で予算を上げてください。

**再現**:

```cal
dates t v1

inputs
  d : date  range >=0001-01-01 <=9999-12-31
  n : int   range >=1 <=100

date x = d
  + n days
```

## W901 — 鍵がファイルに書かれています

**いつ出るか**: ファイルのどこか（文字列でもコメントでも）に、鍵の形の値があるとき。調べる鍵は、AWS のアクセスキー ID、GitHub・Slack・Stripe・OpenAI・Anthropic・Google の鍵やトークン、Slack の Incoming Webhook の URL、PEM の秘密鍵で、どれもプロバイダーが接頭辞や形を決めているものです。ritsu のどの言語も同じ決まりで調べます。診断には鍵の種類と、接頭辞と、長さだけを出し、鍵そのものも、その行も出しません。

**直し方**: 鍵はコードが動くところ（環境変数、プラットフォームの接続やシークレットの置き場）に置き、そこから読んでください。本物の鍵なら、まずプロバイダーで無効にしてください。ファイルから消しても、リポジトリの履歴には残ります。テスト用の値なら、同じ行のコメントに `ritsu: test secret` と書いてください。

**再現**:

```cal
calendar 平日(weekdays) v1

# 事務所の Google カレンダーの API キー: AIzaSyD-ritsu-fake-key-for-tests-000000
closed weekly sat, sun
```
