# rulec

**業務ルールを、業務担当者が読める一枚の表として書き、機械に検査させ、Python と Go の両方に生成する。**

送料、クーポン、ポイント、返品可否 — 業務には「条件が絡み合った判断」がいくつもあります。たいてい `if` 文の泥沼か、設定テーブルか、Excel にあります。そして変えるときにやっていることは、**入れてみて、後から数字を見る**ことです。

rulec は、それを**入れる前に、過去のデータで再生して差分を見る**に変えるための道具です。

---

## 転記した瞬間に、穴が出ます

これが最初の実用価値です。日本郵便のゆうパック運賃表を転記して、47 都道府県を 6 つの群にまとめたとき、県をひとつ書き落とすと:

```
error[E101]: 完全性の欠落: どの行にも当たらない入力があります
  --> rules/ゆうパック運賃.rule:34 表 運賃表
   |
34 | 表 運賃表(fee_table)
   |    ^^^^^^ 入力空間を覆いきっていません
   |
 当たらない例: あて先 = 山梨県, サイズ = S60
 ヒント: この入力に当たる行を足してください。
```

**旧実装も過去データも要りません。** 手元の Excel を転記して `rulec check` に掛けるだけで、穴と重なりが出はじめます。

## 書き方

```
規則 送料例(fee_demo) v1
説明 "README の例。そのまま rulec check を通る"

取込 標準/都道府県

型 サイズ区分(size_class) = S60(s60) | S80(s80) | S100(s100)
群 近畿圏(kinki) = 滋賀県 ・ 京都府 ・ 大阪府 ・ 兵庫県 ・ 奈良県 ・ 和歌山県

入力
  あて先(dest)    : 都道府県
  三辺合計(girth) : 長さ[cm]  範囲 >=1cm <=100cm
  重量(weight)    : 質量[g]   範囲 >=1g <=25kg  契約のみ

出力
  運賃(fee) : 金額[円, 税込]  丸め 切り上げ(10円)

表 サイズ判定(size_of)
方式 上から
| 三辺合計 | → サイズ(size) : サイズ区分 |
| <=60cm   | S60                         |
| <=80cm   | S80                         |
| -        | S100                        |

表 運賃表(fee_table)
方式 一意
| あて先       | サイズ | → 運賃(fee) : 金額[円, 税込] |
| 近畿圏       | S60    | 990円                        |
| 近畿圏       | S80    | 1310円                       |
| 近畿圏       | S100   | 1620円                       |
| 以外: 近畿圏 | S60    | 880円                        |
| 以外: 近畿圏 | S80    | 1200円                       |
| 以外: 近畿圏 | S100   | 1500円                       |

例
| あて先 | 三辺合計 | 重量 | → 運賃 |
| 大阪府 | 55cm     | 1kg  | 990円  |
| 東京都 | 90cm     | 3kg  | 1500円 |
```

この例はそのまま `rulec check` を通ります（リポジトリのテストが毎回確かめています）。

**`例` は実行される仕様です。** 外れたら、どの行が発火したかつきでエラーになります。

## 何を検査するか

| | |
|---|---|
| **完全性** | どの行にも当たらない入力があれば、その具体例つきで止まる |
| **重なり** | `方式 一意` では重なりがエラー。`方式 上から` では、階段の構造的な遮蔽と、出力が食い違って確認に値するものを区別する |
| **冗長** | 決して当たらない行。先行行に覆われている場合と、上流の表が決して出さない値を名指ししている場合を書き分ける |
| **単位** | 円と g を足したら止まる。税込と税抜も別物 |
| **丸め** | 数値出力に丸めの宣言が要る。宣言が無いと「切り捨てなら 0 円、切り上げ(10円)なら 10 円と、丸め方で最大 10 円動きます」と、**円が動くことを数字で見せてから**訊く |
| **溢れ** | 中間値が int64 に収まることを、宣言範囲と刻みから証明する |
| **例** | 全部の例を実行し、外れたら発火行つきで報告する |

すべての診断は業務の言葉で一行目を書き、**具体例（証人）を必ず付け**、ヒントは書き換え後の形まで示します。

## 何をしないか

境界を決めておくことが、この道具が終わるための条件です。

- **汎用の言語にしません。** ループも再帰もありません。停止性は自明です
- **実行時にルールエンジンを積みません。** 生成された普通の関数が動くだけです
- **状態やワークフローを持ちません。** 時刻も在庫も会員区分も、すべて引数で渡します。これが「過去に遡って再生する」ことを意味あるものにしています
- **入れ子のオブジェクトはセルに書けません。** `注文.配送先.都道府県` は境界で平たくして渡します。この制限が、完全性と重複の検査が有限で終わることの土台です
- **不健全な緑を出しません。** 証明できなければ、近似で通さずにエラーで止まります

## 使い方

```console
$ rulec check rules/*.rule
note rules/ゆうパック運賃.rule: 遮蔽 21 対（構造的 21、同値 0、要確認 0）
ok rules/ゆうパック運賃.rule

$ rulec check rules/送料.rule --format json      # GitHub annotations にそのまま流せる形
$ rulec check rules/送料.rule --diff-base HEAD    # 基準から新たに生じた発見だけ
$ rulec fmt --check rules/*.rule                  # gofmt と同じ運用
```

exit code は **0**（注記のみ）、**1**（エラーあり）、**2**（内部異常）です。

## リポジトリの中身

```
DESIGN.md         設計文書。決定と、何を捨てたかの記録
src/              lex / parse / types / region / eval / fmt
tests/corpus/     実在する公開規約を転記した 6 本
tests/mutants/    誤りを一つずつ仕込んだ 18 本
tests/golden/     診断の文面のスナップショット 20 件
tests/budget.rs   検査予算を決めた合成ベンチ
```

コーパスはすべて**公開情報**から作られています — 日本郵便の運賃表、ヤマト運輸のサイズ区分、楽天とヤフーのクーポン規約、労働基準法の割増率。非公開のデータは一つも入っていません。

## いまどこまで来ているか

**M0（検査器）が完成しています。** テスト 47 本、コーパス 6 本、診断は台帳の全項目。

この先は三段あります。

- **M1 生成器** — Python と Go への出力。参照評価器と生成物二つの三者一致をバイト単位で確かめる
- **M2 等価検証** — 旧実装と同じ答えを出すか。**ここで既存システムの未文書化の挙動が出てきます**
- **M3 過去再生** — ルールを変えたら何件・いくら動くかを、PR に自動で付ける

**M0 と M1 は、データも旧実装も本番アクセスも一切要らずに完成します。**

## 設計について

決定と、そのとき何を捨てたかは `DESIGN.md`（1,193 行）にあります。決定表の意味論とヒットポリシーの語彙は DMN から借り、重複・欠落の検出は Calvanese らの定式化に合わせました。借りていないのは XML の交換形式、実行時エンジン、GUI モデラです。そして DMN が面倒を見ない**単位・丸め・二言語へのコード生成・過去再生**が、この道具の差分です。
