# モデル検査器に、生成した Rust を渡す

五つの静的な証明のうち、**生成コードと表の一致はテストのまま**で、**W114 の行対は静的に閉じていない**（README の穴 2 と穴 3）。この二つを、検査器と一行も共有しない道具で閉じられるかを測った場所である。

道具は [Kani](https://model-checking.github.io/kani/)（rustc の MIR を CBMC の GOTO に落とすモデル検査器）。`report.txt` は `run.sh` が 2026-09-20 に rulec 0.10.0 と Kani 0.68.0 / CBMC 6.11.0 に対して印字したものである。短く言うと、**コーパス 30 本・ハーネス 73 本が全部通り、合計 155 秒**だった。

## 分かったこと三つ

**① 生成物は、五つのうち三つを既に assert として持っていた。** 表の末尾の `unreachable!` が完全性、W114 のガードの `Contradiction` が未証明の行対、そして i64 の演算そのものがあふれの主張である。Kani は panic の到達可能性と算術のあふれを既定で見るので、ハーネスは「宣言した範囲を仮定して、関数を呼ぶ」だけでよい。

**② 唯一の壁は `format!` だった。** 3 行の規則でも CBMC が 10 分で終わらない。切り分けると、trace の `Vec` は 0.15 秒、規則の論理は 1 秒未満、**`format!("...: {}", 記号的な i64)` だけで 10 分を超えて終わらない**（二度測った）。エラー文が値を埋め込むのをやめた同じ生成物は **0.80 秒**で通った。§15.95 の「文と値を分ける」はこの測定である。

**③ 重なり（E105）は、生成物からは再検査できない。** if / else if の連鎖が優先順位に潰してしまっているので、`unique` の重なりは rulec がガードを置いた対以外どこにも現れない。だから行の条件を別に持ち上げて数える（`rows_<表>`）。最初の測定は生成された Rust から正規表現で取り出してやり（`extract.py`、40 行。コーパス 30 本から表 45 個・行 355 本が取れた）、そのうえで生成器が IR から直接書くようにした。`extract.py` は、その第一歩がどれだけ小さかったかの記録として置いてある。

## 空振りでないことの確認

変異を二つ入れて確かめた（`印紙税` の行の条件に対して）。

| 変異 | 出たもの |
|---|---|
| 行 5（500,001〜1,000,000 円）を消す | `契約金額 = 804,896円 / 作成日 = 2026-10-11 / 記載あり` で当たる行が無い |
| 行 3 の上限を 10万円 → 50万円 に広げる | `108,304円 / 2030-12-25` で二行に当たる |

どちらも具体的な入力つきで落ちる。Kani の `--concrete-playback` はその入力をそのままテストとして書き出す。

## 何が言えて、何が言えないか

言えるのは、**この Rust が、宣言した範囲のどの入力でも、穴に落ちず・ガードに当たらず・i64 をあふれさせずに答える**ことと、**`unique` の表の行がその範囲をちょうど一度ずつ覆う**ことである。区画の検査（箱の代数）とは共有するコードが無いので、二つが食い違えばどちらかにバグがある——それが走らせる理由である。

言えないのは、表と現実の一致（`@source` の領分）と、残り 11 言語の生成物（Kani は Rust だけを読む）。そして Kani が通ったことは**生成物についての証明**であって、**表についての証明ではない**（§15.47）。

## ここにあるもの

- `run.sh` — 測定の全部。`cargo build --release` の後、`kani` を PATH に置いて走らせる。
- `report.txt` — それが印字したもの。
- `extract.py` — 生成された Rust から行の条件を持ち上げる 40 行。生成器が同じことをするようになったので、もう使われていない。

```console
$ cargo build --release
$ sh experiments/kani/run.sh
```

CI は同じことを毎回やる（`.github/workflows/ci.yml` の「The proofs hold, for every rule in the corpus」）。手元では `rulec test --proofs` が同じ段を走らせる。
