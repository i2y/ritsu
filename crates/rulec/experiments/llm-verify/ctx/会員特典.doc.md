# 規則 会員特典 v1

会員区分と重量から請求額とポイントを一度に出す。出力が二つ、result が一本、率が表の列から来る例

## 入力

| 名前 | 型 | 範囲 | 注記 |
|---|---|---|---|
| 会員区分 | 会員（2 値） |  |  |
| 重量 | mass[g] | 1g 〜 2万g |  |
| 商品合計 | money[円, incl_tax] | 0円 〜 100万円 |  |
| 値引 | money[円, incl_tax] | 0円 〜 10万円 |  |

## 出力

| 名前 | 型 | 丸め | 注記 |
|---|---|---|---|
| 請求額 | money[円, incl_tax] | half_up(10円) |  |
| 付与点 | number | down(1) |  |

## 型

列挙は**閉じた**有限集合です。値を足すと、それを見ていない表が完全性検査で割れます。

- **会員**（2 値）— 一般、上位
- **重さ区分**（3 値）— 軽、中、重
- **帯**（3 値）— 銅、銀、金

## 導出と定義

表の列に置ける中間の値です。式はもとの規則のとおりで、範囲は宣言されたものです。

| 名前 | 種類 | 式 | 範囲 | 注記 |
|---|---|---|---|---|
| 支払額 | 導出 | `商品合計 - 値引` | -10万円 〜 100万円 |  |
| 基本点 | 定義 | `商品合計 ÷ 100円` |  |  |
| 付与点 | 定義 | `基本点 × 倍率` |  |  |

導出の宣言範囲が、入力範囲から実際に到達しうる値をすべて含んでいることは `rulec check` が確かめました（E112）。

## 表 重さ判定（policy first）

| 列 | 出どころ |
|---|---|
| 重量 | 入力 |
| → 区分 | → 表 帯判定 の入力列 |

| # | 重量 | → 区分（重さ区分） |
|---|---|---|
| 1 | <=2kg | 軽 |
| 2 | <=10kg | 中 |
| 3 | - | 重 |

行3 はすべての列が `-` なので、上のどれにも当てはまらない入力が落ちる**既定行**です。

**`rulec check` が確かめたこと**

- どの入力の組合せも、いずれかの行に当てはまります（E101 完全性）
- どの入力にも当てはまらない行はありません（E102）
- 行の重なりは 3 対あります（先に書いた行が後ろを隠すだけの**階段** 3、どちらが勝っても値の変わらない**同じ答え** 0、出力が食い違うので**要確認** 0）。`policy first` なので、先に書かれた行が勝ちます
