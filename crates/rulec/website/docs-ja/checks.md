# 何を証明するか

`rulec check` がこの道具の中心です。生成もベクタも再生も、全部その下流にあり、**検査を通らない規則からは何も生成されません**。

```console
$ rulec check rules/ --lang ja
note rules/ゆうパック運賃.rule: 遮蔽 21 対（構造的 21、同値 0、要確認 0）
ok rules/ゆうパック運賃.rule
```

exit code は **0**（注記のみ）、**1**（エラーあり）、**2**（引数の誤りか読めないファイル）。**出力が空に見えるかどうかではなく、exit code を読んでください。**

## 七つ

| | |
|---|---|
| **完全性** | どの行にも当たらない入力があれば、**その入力つきで**止まる |
| **重なり** | `policy unique` では重なりがエラー。`policy first` では、階段の構造的な遮蔽と、出力が食い違って確認に値する対とを区別する |
| **冗長** | 決して当たらない行。先行行に覆われている場合と、上流の表が決して出さない値を名指ししている場合を書き分ける |
| **単位** | 円と g を足したら止まる。税込と税抜も別物 |
| **丸め** | 数値出力に丸めの宣言が要る。無ければ「切り捨てなら 701 円、四捨五入なら 702 円、`up(10円)` なら 710 円と、丸め方で最大 9 円動きます」と、**円が動くことを数字で見せてから**訊く |
| **溢れ** | 中間値が int64 に収まることを、宣言範囲と刻みから証明する |
| **例** | 全部の例を実行し、外れたら発火行つきで報告する。出力の列が欠けていたら止める |

すべての診断は業務の言葉で一行目を書き、**具体例（証人）を必ず付け**、ヒントは書き換え後の形まで示します。

## 診断の読み方

```
error[E101]: 完全性の欠落: どの行にも当たらない入力があります
  --> rules/ゆうパック運賃.rule:34 表 運賃表
   |
34 | table 運賃表(fee_table)
   |       ^^^^^^ 入力空間を覆いきっていません
   |
 当たらない例: あて先 = 山梨県, サイズ = S60
 ヒント: この入力に当たる行を足してください。
 足す行の形: `| 山梨県 | S60 | 820円 |`。出力の値は表の一行目から写した「形」で、正しい額ではありません。…
```

考えるべきは**証人**です。`あて先 = 山梨県, サイズ = S60` は例示ではありません — 検査器が実際に構成した入力であり、答えを知っている人にそのまま渡せる一文です。

### 件数が多いとき: `--terse`

```console
$ rulec check rules/ --terse --lang ja
error[E101]: 完全性の欠落: どの行にも当たらない入力があります
  --> rules/ゆうパック運賃.rule:34 表 運賃表
  証人: あて先 = 山梨県, サイズ = S60
…
details: rulec explain <code>
```

見出し・位置・証人の三行。残りへの道案内は、走査の最後に一度だけ出ます。

### プログラムが読むとき: `--format json`

同じ発見をデータで。文面も残りますが、下流が**文を解析する必要はありません**。

```console
$ rulec check rules/ゆうパック運賃.rule --format json | jq -c 'select(.code=="E101") | {table:.where.table, witness:.witness.inputs, fix:.fix}'
{"table":"運賃表","witness":{"あて先":"山梨県","サイズ":"S60"},"fix":{"kind":"add_row","text":"| 山梨県 | S60 | 820円 |"}}
```

`where` がどの表のどの行か、`witness` が正準単位での値の割り当て、`rows` が関与する行の全部、`fix` が貼れる書き換え後の形です。**`witness` と `fix` は `--lang` で変わりません** — 変わるのは名前が文面だと言っている欄だけです。形式の定義は [形式](formats.md#check) にあります。

!!! warning "`fix.text` は「形」であって「判断」ではない"

    構文として通ること、そのコードが消えることは、どちらもテストで確かめてあります。しかし**正しい金額も、丸めの向きも、格子も知りません**。それは業務の判断です。注意書きは文面である `notes` の側にあります — `fix.text` はバイト列だからです。

## コードを引く

どのコードにも台帳の項目があります。いつ出るか、どう直すか（書き換え後の形まで）、**走る最小の再現**、関係するコード。

```console
$ rulec explain E101 --lang ja
error[E101]: 完全性の欠落: どの行にも当たらない入力があります

いつ出るか
  表の行の和が、宣言した入力空間を覆いきっていないとき。…

直し方
  証人の入力に当たる行を足してください。…

最小の再現
  rule t(t) v1

  enum k(k) = a(a) | b(b) | c(c)
  …

関係するコード: E102 E105 W111
```

`rulec explain --all --format markdown` が台帳の全部で、このサイトの [診断コード](codes.md) は**その出力そのもの**です。台帳の再現は全部テストが走らせているので、「文章は立派だが実はもう嘘」という腐り方をしません。

## 新しく出たものだけ

```console
$ rulec check rules/ --diff-base origin/main
```

基準リビジョンに既にあった発見は伏せられ、伏せた件数が出ます。対は行番号ではなく**セルの正準形**で照合するので、行を一つ挿しただけで全部が新規に見えることはありません。

これが CI で警告を使いものにします。意図した `policy first` の遮蔽を何年も抱えたままの表があっても、**この変更が持ち込んだ一件**が埋もれません。

## 証明できないとき

そう言います。近似して通すことはしません。

- **E109** — 検査の予算を超えたので完全性を証明できなかった。表を分けるか `--budget` を上げてください。何も仮定しません。
- **W114** — `unique` の表の二行が重なりうるが、それを起こす入力を構成できず、実現不能の証明もできなかった。警告を出し、**生成コードには番人が入ります** — 万一その条件に当たる入力が来たとき、黙って先の行を選ばずエラーを返します。番人が発火したなら、その重なりは実在したということです。

## 承認する人に見せる

```console
$ rulec doc rules/ゆうパック運賃.rule --lang ja > 運賃.md
```

`.rule` は既にほぼ markdown なので、**構文の転写には価値がありません**。`doc` の仕事は、**検査器が知っていて字面に現れない事実を添える**ことです — 6 値の群とその補集合 41 値が本当に 47 を覆っていること、どの行がどの行を遮蔽しているか、どの丸めが出典なしの仮置きか。

禁則が一つあります。**検査器の出力に無い文章は書きません。** すべての行が原本か検査結果に遡れ、事実の出どころも「`rulec check` が確かめました」と「この描画が宣言から数えました」で名乗り分けます。コミットはしません — CI が生成して PR に貼ります。古い描画が現在の真実の顔をして残るのが、この設計が避けている最大の危険だからです。
