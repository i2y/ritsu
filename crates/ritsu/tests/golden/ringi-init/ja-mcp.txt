# approvals

申請と承認のサーバーです。決まりは `project/` に ritsu の申請の言語で書き、ritsu がそこから Go のコードと約束のファイルを生成し、フレームワークがそれを動かします。人がブラウザで使うページと API があります。フレームワークは Go のモジュール `github.com/i2y/ringi-server` です。

英語版：[README.md](README.md)

`ritsu ringi init` が始めの形として書いたファイルです。申請の種類が一つ、小さな組織、gate、サーバーがあります。ここからは自分のファイルとして、自分の決まりに書き換えてください。

## 中身

| ファイル | 中身 |
|---|---|
| `project/purchase.ringi` | 申請の種類。フォーム、二つのステップの経路、期限、どう進むかを書いたシナリオ |
| `project/shared/company.ringi` | 組織の形。役職とチームの種類 |
| `project/org/2026-04-01/` | その日からの組織のデータ。チーム、人、所属を CSV で |
| `project/shared/office.cal` | 期限を数える営業日 |
| `project/shared/company.gate` | チケットに、だれが何をできるか |
| `go/`、`requests/` | ritsu が `project/` から生成した物（手で直さない） |
| `generate.go` | 生成し直すときに `go generate` が走らせる行 |
| `approvals.go` | プロジェクトがサーバーに渡す物。申請の種類、組織、gate、通知 |
| `gate.go` | サーバーの問いを、生成した gate につなぐ所 |
| `notify.go` | 通知をログに書く部品 |
| `tools.go` | サーバーの `/mcp` で、エージェントのツールを MCP で出す所 |
| `cmd/server/` | サーバー |
| `*_test.go` | 試験 |

## 動かす

```sh
go mod tidy
go run ./cmd/server -dev-login
```

ブラウザで http://127.0.0.1:8080/pages/ を開き、だれとして使うかを選びます。営業一課の担当 `s1201` が購買を申請し、課長の `s1101` が承認し、次に営業部長の `s1001` が承認します。通知はログに出ます。`-dev-login` は本人を確かめないので、このコンピューターの中だけで動きます。

エージェントのツールは http://127.0.0.1:8080/mcp にあり、MCP の streamable HTTP で使います。エージェントは、ブラウザと同じ仕方でログインします。`-dev-login` のときはクッキー `ringi-dev-person=s1201` を送り（ブラウザでは `/login` のページが置きます）、ログインのフラグが無いときはヘッダ `X-Person: s1201` を送ります。ツールでしたことは、ページと同じく gate に尋ねられます。

## 決まりを変える

`project/` のファイルを書き換えたら、検査して、コードを生成し直します。

```sh
ritsu check project
go generate ./...
go test ./...
```

`ritsu check` は、シナリオを一つずつ走らせ、決まりが言い切っていることを確かめます。だれの申請がどこへ回るかは、`ritsu ringi simulate project/purchase.ringi --every-requester` で見られます。CI では、`generate.go` の行に `--check` を付けて走らせます。何も書かず、`go/` か `requests/` が `project/` から作られる物と違えば落ちます。

組織のデータはプログラムに組み込まれます。組織が変わるときは、効き始める日の名前のディレクトリ `project/org/<日付>/` を足します。サーバーは起動し直したときに読みます。動いているサーバーには、起動し直さずに取り込ませることもできます。それをするのは、ログインで役割 `system_admin` を持つ人です（`-dev-login` では、ログインのページで役割を選びます）。`ritsu check project` でデータを確かめ、`project/` から `org/` を zip にまとめて、ページ `/pages/admin/organization` で上げます。

```sh
cd project && zip -r ../org.zip org -x '*/.*'
```

ページは、新しいデータで変わることを日ごとに見せ、確かめたあとで取り込みます。同じ版を `project/org/` にも足しておきます。起動し直したサーバーは、組み込んだデータが前に取り込んだときから変わったときだけ取り込むからです。取り込みも申請の種類の版の切り替えも、`/pages/admin/records` が見せる記録に残ります。

## 試験

`go test ./...` は四つの試験を走らせます。

- `TestVectors`：ritsu が決まりとシナリオから `requests/vectors/` に書いたベクタを、全部サーバーに渡し、答えを確かめます。
- `TestGate`：gate だけが決めること（自分の載っていないチケットをだれが見られるか、だれが取り下げられるか、管理の四つの操作を役割と部署でだれができるか）で、`gate.go` を確かめます。組織の版に居ない人と、持ち主を書かない申請の種類が、どの部署にも当たらないことと、gate が宣言していない役割を外して尋ねることも確かめます。
- `TestPages`：開発用のログインでページから申請を出し、承認します。
- `TestTools`：`cmd/server` と同じく、`/mcp` にエージェントのツールを置いてプロジェクトを動かします。`s1201` のエージェントがツールで購買を申請して読み、だれもログインしていないリクエストには 401 が返ることを確かめます。

## 人に使ってもらう

フラグの一覧は `go run ./cmd/server -h` で出ます。

- **チケットを置く所**：`-db 'postgres://…'` で、PostgreSQL のスキーマ `ringi` に置きます。添付もそこに置きます。`-db` が無ければメモリに置き、サーバーを止めると消えます。
- **ログイン**：OpenID Connect のプロバイダーでログインするには、`-oidc-issuer`、`-oidc-client-id`、`-oidc-redirect-url https://<サーバーのホスト>/login/callback` を渡し、クライアントのシークレットとセッションのクッキーの鍵を、環境変数 `RINGI_OIDC_CLIENT_SECRET` と `RINGI_SESSION_KEYS`（32 バイトずつの base64、新しい順）に置きます。プロバイダーが返すメールアドレスを組織のデータに持つ人が、その人になります。これらのフラグも `-dev-login` も無ければ、人はヘッダ `X-Person` で決まります。前に置いたプロキシーが、人をログインさせてから付けるヘッダです。このときサーバーは、ループバックのアドレスでだけ待ち受けます。
- **https**：`-tls-cert` と `-tls-key` を渡し、`-addr` を人が届くアドレスにします。
- **エージェントのツール**：`/mcp` は、ページと同じ仕方で人を見つけます。プロバイダーでログインするときは、エージェントに、ブラウザでログインしたセッションのクッキーが要ります。ベアラートークンで受けたいときは、自分の HTTP のサーバーに、`mcp.HTTP{Verify: …}` でツールを置きます。やり方はモジュール `github.com/i2y/ringi-server/mcp` の README にあります。

だれでもだれにでもなれてしまう設定は、サーバーが断ります。`-dev-login` やヘッダを、`-tls-cert` と一緒に使うこと、ほかのコンピューターから届くアドレスで使うこと、プロバイダーの設定がある所で使うことです。

## 申請の種類を足す

`purchase.ringi` の横に `project/<名前>.ringi` を書き、組織、カレンダー、gate の `use` の行は同じ物にします。そのあと `ritsu check project`、`go generate ./...`、`go test ./...` を走らせます。新しい種類のシナリオはベクタになり、`TestVectors` が走らせます。マスタを読む種類なら、そのデータも組み込むため、`approvals.go` の `//go:embed project/org` の行にそのディレクトリを足します。`gate.go` は action の名前で gate に尋ねるので、gate に action を足しても `gate.go` は変えなくてかまいません。principal や resource に属性を足したら、その値を `gate.go` の `gateStore` に足します。gate が Staff に持たせる役割は生成したコードの `RolesOf` が答えるので、gate に役割を足しても `gate.go` は変えなくてかまいません。

## flow を足す

flow は、チケットが終わったあとやステップの中で動く仕事です（支払い、エージェントの確かめなど）。申請の種類に `use flow <名前> from "shared/<名前>.flow"` と書き、`launch` か `ask` で使います。`go generate ./...` が、その Go のパッケージを `go/flows/` に書きます。サーバーは flow を `server.Config.Flows` で（エージェントのステップは `Agents` で）始めます。flow を動かすのはフレームワークのモジュール `github.com/i2y/ringi-server/temporal` で、サーバーへの渡し方とワーカーの動かし方はその README にあります。渡すまでのあいだ、サーバーは始められない flow を「すること」として残し、試し直すたびにログに書きます。

# approvals

Requests and approvals: the rules are written in ritsu's request language under `project/`, ritsu
generates the Go code and the contract from them, and the framework serves them, with the pages
people use in a browser and the API. The framework is the Go module `github.com/i2y/ringi-server`.

Japanese: [README.ja.md](README.ja.md).

`ritsu ringi init` wrote these files as a start: one request type, a small organization, a gate and
a server. They are yours now: change them into your own rules.

## What is in it

| File | What it is |
|---|---|
| `project/purchase.ringi` | The request type: its form, its route of two stages, its deadlines, and scenarios that say what happens |
| `project/shared/company.ringi` | The shape of the organization: the positions and the kinds of team |
| `project/org/2026-04-01/` | The organization's data from that day: its teams, people and members, as CSV |
| `project/shared/office.cal` | The business days the deadlines count |
| `project/shared/company.gate` | Who may do what on the tickets |
| `go/`, `requests/` | What ritsu generates from `project/` (do not edit them) |
| `generate.go` | The line `go generate` runs to generate them again |
| `approvals.go` | What the project gives the server: its kinds, organization, gate and notifier |
| `gate.go` | The glue between the server's questions and the generated gate |
| `notify.go` | A notifier that writes each notice to the log |
| `tools.go` | The agents' tools at `/mcp` of the server, over MCP |
| `cmd/server/` | The server |
| `*_test.go` | The tests |

## Running it

```sh
go mod tidy
go run ./cmd/server -dev-login
```

Open http://127.0.0.1:8080/pages/ in a browser and choose who you are. `s1201` (a member of the
staff of Sales Section 1) makes a purchase request; `s1101`, the section's manager, approves it,
then `s1001`, the head of the Sales Department. The notices go to the log. `-dev-login` checks no
one: it serves this computer only.

The agents' tools are at http://127.0.0.1:8080/mcp, over MCP's streamable HTTP. An agent signs in
as a browser does: with `-dev-login`, it sends the cookie `ringi-dev-person=s1201` (the page `/login`
sets it in a browser); with no flag of a sign-in, the header `X-Person: s1201`. What it does with the
tools is asked of the gate, as on the pages.

## Changing the rules

Change the files of `project/`, then check them and generate the code again:

```sh
ritsu check project
go generate ./...
go test ./...
```

`ritsu check` runs each scenario and checks what the rules claim; `ritsu ringi simulate
project/purchase.ringi --every-requester` shows where each person's request goes. In CI, run the
line of `generate.go` with `--check`: it writes nothing, and fails when `go/` or `requests/` is not
what `project/` makes.

The organization's data is built into the program: a new version of it is a directory
`project/org/<the day it takes effect>/`, and the server reads it when it starts again. A server that
runs takes it without starting again, from a person whose sign-in gives them the role
`system_admin` (with `-dev-login`, chosen on its sign-in page). Check the data with
`ritsu check project`, put `org/` into a zip archive from `project/`, and upload the archive on the
page `/pages/admin/organization`:

```sh
cd project && zip -r ../org.zip org -x '*/.*'
```

The page shows what the new data changes, day by day, and imports it when you confirm. Add the same
version to `project/org/` too: a server started again imports the data built in only when it changed
since the server last imported it. Each import, and each switch of a version of a request type, is
kept in the record that `/pages/admin/records` shows.

## Tests

`go test ./...` runs four tests:

- `TestVectors` gives the server every vector ritsu wrote in `requests/vectors/` from the rules
  and the scenarios, and checks its answers.
- `TestGate` checks `gate.go` on what only the gate decides: who sees a ticket they are not on, and
  who withdraws one; who may do each of the four operations of the administration, by role and by
  department; that a person the organization's version does not have, and a request type that names
  no owner, are of no one's department; and that a role the gate does not declare is left out.
- `TestPages` makes a request on the pages with the development sign-in, and approves it.
- `TestTools` serves the project as `cmd/server` does, with the agents' tools at `/mcp`: an agent of
  `s1201` makes a purchase request with the tools and reads it, and a request with no one signed in
  is answered 401.

## Running it for people

`go run ./cmd/server -h` lists every flag.

- **Where the tickets are kept**: `-db 'postgres://…'` keeps them in PostgreSQL, in the schema
  `ringi`, with the attachments. Without `-db`, they are kept in memory and lost when the server
  stops.
- **How people sign in**: through an OpenID Connect provider, with `-oidc-issuer`,
  `-oidc-client-id`, `-oidc-redirect-url https://<the server's host>/login/callback`, and the
  client's secret and the keys of the session cookies in the environment variables
  `RINGI_OIDC_CLIENT_SECRET` and `RINGI_SESSION_KEYS` (base64 of 32 bytes each, the newest first).
  A person is the one of the organization's data with the email address the provider gives. Without
  these flags, and without `-dev-login`, the person is the header `X-Person`, which a proxy in front
  of the server sets after it signs people in; the server then listens on a loopback address only.
- **https**: `-tls-cert` and `-tls-key`, with `-addr` on the address people reach.
- **The agents' tools**: `/mcp` finds the person as the pages do. With a provider, an agent needs
  the cookie of a session signed in from a browser. To take bearer tokens instead, serve the tools
  with `mcp.HTTP{Verify: …}` on a server of your own: the README of the module `github.com/i2y/ringi-server/mcp`
  shows how.

The server refuses settings that would let anyone be anyone: `-dev-login` or the header with
`-tls-cert`, on an address other computers reach, or where the provider's settings are.

## Adding a request type

Write `project/<name>.ringi` beside `purchase.ringi`, with the same `use` lines for the organization,
the calendar and the gate, then run `ritsu check project`, `go generate ./...` and `go test ./...`.
The new type's scenarios become vectors that `TestVectors` runs. A type that reads masters needs
their data built in too: add their directory to the `//go:embed project/org` line of
`approvals.go`. `gate.go` asks the gate by the action's name, so an action added to the gate needs
no change there; an attribute added to a principal or a resource needs its value in `gateStore`. A
role the gate lets a Staff hold is in `RolesOf`'s answer, so one added to the gate needs no change
either.

## Adding a flow

A flow is work that runs after a ticket ends or in a stage of it, such as a payment or an agent's
check: `use flow <name> from "shared/<name>.flow"` in the request type, and `launch` or `ask` it.
`go generate ./...` writes its Go package under `go/flows/`. The server starts flows through
`server.Config.Flows`, and an agent's step through `Agents`. The framework's module that runs them
is `github.com/i2y/ringi-server/temporal`:
its README shows how to give them to the server and run their workers. Until a server has them, it
keeps each start it cannot make as a thing to do, and says so in the log each time it tries again.

// Package approvals runs the requests of project/ on the framework: the package ritsu generated
// from them (go/ and requests/, which go generate writes again), with the gate (gate.go) and a
// notifier that writes to the log (notify.go). cmd/server is the server.
//
// The server serves the agents' tools at /mcp too (tools.go).
package approvals

import (
	"embed"
	"io/fs"
	"log/slog"

	server "github.com/i2y/ringi-server"
	"github.com/i2y/ringi-server/orgfiles"

	"example.com/acme/approvals/go/ticketkinds"
)

//go:embed requests/openapi.json requests/types requests/a2ui requests/mcp
var requests embed.FS

//go:embed project/org
var project embed.FS

// Package loads the generated package: the kinds of request, with the files of the contract the
// server reads, built into the program. The vectors are not built in: they are for the tests.
func Package() (*server.Package, error) {
	dir, err := fs.Sub(requests, "requests")
	if err != nil {
		return nil, err
	}
	return PackageFrom(dir)
}

// PackageFrom loads the generated package from dir, a directory laid out as requests/ is: the
// tests load it from the disk, where the vectors are.
func PackageFrom(dir fs.FS) (*server.Package, error) {
	return server.Load(ticketkinds.Contract, ticketkinds.Lang, ticketkinds.Kinds, dir)
}

// Organization reads the organization's data in project/org: a directory for each version, named
// by the day it takes effect.
func Organization() server.OrgSource {
	dir, err := fs.Sub(project, "project")
	if err != nil {
		panic(err)
	}
	return orgfiles.New(dir)
}

// Parts are what the project gives the server: its kinds, its organization, its gate and its
// notifier, which write what they have to say in log. cmd/server adds where the tickets are kept and
// how people sign in, from its flags. Once the server is made, Started gives the notifier the server.
func Parts(log *slog.Logger) (server.Config, error) {
	p, err := Package()
	if err != nil {
		return server.Config{}, err
	}
	return server.Config{
		Packages:     []*server.Package{p},
		Gate:         &Gate{Log: log},
		Organization: Organization(),
		Notifier:     &LogNotifier{Log: log, Lang: "ja"},
	}, nil
}

// Started gives the parts of cfg that read the server the server made from cfg (by server.New, or
// in the function Serve calls once it is made): the notifier, which says each kind by its title.
func Started(cfg server.Config, srv *server.Server) {
	if n, ok := cfg.Notifier.(*LogNotifier); ok {
		n.Server = srv
	}
}

// Command server serves the requests of the project: the pages people use in a browser, and the
// API. Where it keeps the tickets and how people sign in come from its flags:
//
//	go run ./cmd/server -dev-login
//
// lets you choose who you are on a page, on this computer only (-addr stays on 127.0.0.1). Without
// -dev-login, the person is the header X-Person, which a proxy in front of the server sets after it
// signs people in; with -oidc-issuer, -oidc-client-id and -oidc-redirect-url, the server signs
// people in with an OpenID Connect provider. -db keeps the tickets in PostgreSQL; without it, they
// are kept in memory and lost when the server stops. go run ./cmd/server -h lists every flag.
//
// The agents' tools are at /mcp (HandleTools): an agent signs in as a browser does.
package main

import (
	"context"
	"flag"
	"log/slog"
	"os"
	"os/signal"
	"syscall"

	server "github.com/i2y/ringi-server"
	"github.com/i2y/ringi-server/serve"

	"example.com/acme/approvals"
)

func main() {
	var flags serve.Flags
	flags.Register(flag.CommandLine)
	flag.Parse()
	log := slog.New(slog.NewTextHandler(os.Stderr, nil))
	if err := run(flags, log); err != nil {
		server.LogStop(log, "the server stopped", err)
		os.Exit(1)
	}
}

func run(flags serve.Flags, log *slog.Logger) error {
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()
	stores, err := serve.Open(ctx, flags, log)
	if err != nil {
		return err
	}
	defer stores.Close()
	cfg, err := approvals.Parts(log)
	if err != nil {
		return err
	}
	approvals.HandleTools(stores, log)
	return stores.Serve(ctx, cfg, func(srv *server.Server) { approvals.Started(cfg, srv) })
}

package approvals

import (
	"context"
	"errors"
	"log/slog"
	"slices"
	"sync"

	server "github.com/i2y/ringi-server"

	"example.com/acme/approvals/go/authz/company"
)

// Gate asks the gate ritsu generated from project/shared/company.gate (go/authz/company), with what
// the framework's question says. The gate's Requesters and Approvers are groups: the person is in
// them when the question lists them. An attribute added to a principal or a resource needs its
// value in gateStore; a role the gate lets a Staff hold is in the answer of the generated RolesOf,
// so one added to the gate needs no change here.
type Gate struct {
	// Log is where Gate says a role a sign-in gives that the gate does not declare: once for each
	// role, for the first hundred of them.
	Log *slog.Logger

	mu   sync.Mutex
	told map[string]bool
}

// gateRoles are the roles a Staff principal of project/shared/company.gate can hold, in the order
// the gate declares them: the generated package's RolesOf, asked by the principal's type in Cedar.
// The generated gate refuses a person with a role it does not declare, whatever they ask, so Allow
// leaves out a role the sign-in gives for something else (a claim of the provider, a header of the
// proxy).
func gateRoles() []string {
	return company.RolesOf("Staff")
}

// Allow asks the gate by the action's name, with the ID of each resource the framework knows: the
// ticket, its stage, its kind of request (the version the question is of), and the organization.
// The gate takes the one its action asks about. An action the gate does not declare is an error;
// the gate's other refusals are a no, a person it does not read (one with no primary team in the
// organization's version) among them.
func (g *Gate) Allow(_ context.Context, q server.Question) (bool, error) {
	ids := map[string]string{"Ticket": q.Ticket, "Stage": q.Ticket + "/" + q.Stage, "RequestType": q.Kind, "Organization": "organization"}
	store := gateStore{q: q, roles: g.roles(q.Person)}
	a := company.Authorize(store, company.Principal{Type: "Staff", ID: q.Person.ID}, q.Action, ids, q.Now)
	if a.Err != nil && a.Err.Kind == "action" {
		return false, errors.New(a.Err.Message)
	}
	return a.Err == nil && a.Allowed, nil
}

// roles answers the roles of the person the gate declares, in the order the sign-in gives them:
// staff when it gives none of them. A role left out is said in the log.
func (g *Gate) roles(p server.Person) []string {
	declared := gateRoles()
	var kept []string
	for _, r := range p.Roles {
		switch {
		case !slices.Contains(declared, r):
			g.leftOut(r, p.ID)
		case !slices.Contains(kept, r):
			kept = append(kept, r)
		}
	}
	if len(kept) == 0 {
		return []string{"staff"}
	}
	return kept
}

// leftOut says in the log that the gate does not declare role, the first time a sign-in gives it.
// It keeps the names of a hundred roles at the most, as the names come from outside.
func (g *Gate) leftOut(role, person string) {
	g.mu.Lock()
	defer g.mu.Unlock()
	if g.told[role] || len(g.told) >= 100 {
		return
	}
	if g.told == nil {
		g.told = map[string]bool{}
	}
	g.told[role] = true
	if g.Log != nil {
		g.Log.Warn("the gate does not declare a role the sign-in gives, and is asked without it", "role", role, "person", person)
	}
}

// gateStore is what the gate reads, from one question.
type gateStore struct {
	q     server.Question
	roles []string
}

// Staff answers the person as the gate reads them, or nil for one the organization's version does
// not have (no primary team in it): the gate refuses them whatever they ask, so that no one outside
// the organization is taken as one of a department. Their department is their team of the kind of
// the team that owns the request type, the first team of that kind at or above their primary team:
// a request type owned by a section, a department or a division is compared at its own level,
// whatever the organization calls its kinds of team. A question with no owner among the version's
// teams (one of the organization, or of a request type that names no owner or a team the version
// does not have) gives their primary team, which owns nothing of it.
func (s gateStore) Staff(id string) (*company.Staff, error) {
	kind := ""
	if owner, ok := teamIn(s.q.Org, s.q.Owner); ok {
		kind = owner.Kind
	}
	department := s.q.Org.TeamOf(id, kind)
	if department == "" {
		return nil, nil
	}
	st := &company.Staff{Department: department}
	if id == s.q.Person.ID {
		st.Roles = s.roles
		if slices.Contains(s.q.Requesters, id) {
			st.MemberOfRequesters = []string{"requesters"}
		}
		if slices.Contains(s.q.Approvers, id) {
			st.MemberOfApprovers = []string{"approvers"}
		}
	}
	return st, nil
}

func (s gateStore) Stage(string) (*company.Stage, error) {
	return &company.Stage{Requester: s.q.Requester, Requesters: "requesters", Approvers: "approvers", Owner: s.owner(), SelfApproval: s.q.SelfApproval}, nil
}

func (s gateStore) Ticket(string) (*company.Ticket, error) {
	return &company.Ticket{Requester: s.q.Requester, Requesters: "requesters", Owner: s.owner()}, nil
}

func (s gateStore) RequestType(string) (*company.RequestType, error) {
	return &company.RequestType{Owner: s.owner()}, nil
}

// owner answers the team that owns the request type. One that names no owner is owned by no team:
// the gate is given an ID that no team of the organization's version has, so that it is no one's
// department, and only a rule that reads no department (a system administrator's) allows anything
// of it.
func (s gateStore) owner() string {
	if s.q.Owner != "" {
		return s.q.Owner
	}
	id := "(no owner)"
	for {
		if _, ok := teamIn(s.q.Org, id); !ok {
			return id
		}
		id = "(" + id + ")"
	}
}

// teamIn answers the team of the version v with the ID id, and whether it has one.
func teamIn(v *server.OrgVersion, id string) (server.Team, bool) {
	if v != nil {
		for _, t := range v.Teams {
			if t.ID == id {
				return t, true
			}
		}
	}
	return server.Team{}, false
}

import (
	"context"
	"log/slog"
	"strings"

	server "github.com/i2y/ringi-server"
)

// LogNotifier writes each notice to the log, where a real one sends a mail or a chat message: the
// notice names the people to tell, with their addresses from the organization's data. It says the
// kind by its title in the language it writes in (Server.Title), with the language the title is in:
// the kind's title as its file writes it where it has none in that language. A real one writes to
// each person in their own language, and sends each key once: the framework calls it again with the
// same key after a failure it could not tell from a success.
type LogNotifier struct {
	// Server is the server whose kinds the notices are of; Started sets it once the server is made.
	Server *server.Server
	Log    *slog.Logger
	// Lang is the language the notices are written in; "en" when empty.
	Lang string
}

// Notify writes the notice.
func (n *LogNotifier) Notify(_ context.Context, x server.Notice) error {
	to := make([]string, 0, len(x.To))
	for _, r := range x.To {
		to = append(to, r.ID+" "+r.Email)
	}
	lang := n.Lang
	if lang == "" {
		lang = "en"
	}
	title, in := n.Server.Title(x.Kind, x.Version, lang)
	n.Log.Info("notice", "notice", x.Notice, "to", strings.Join(to, ", "), "kind", x.Kind, "title", title, "title_lang", in, "ticket", x.Ticket, "stage", x.Stage)
	return nil
}

// TestPages makes a purchase request on the pages, as people do in a browser with go run
// ./cmd/server -dev-login: the requester signs in and submits the form, the manager is told and
// approves, and the head of the department approves.
func TestPages(t *testing.T) {
	var log bytes.Buffer
	dev := &devlogin.SignIn{}
	srv := newServer(t, dev, &log)
	h, err := web.New(srv, web.Config{Require: dev.Require, LoginURL: dev.LoginURL, SignOut: devlogin.LogoutPath, Logger: slog.New(slog.NewTextHandler(&log, nil))})
	if err != nil {
		t.Fatal(err)
	}
	dev.Server = srv
	dev.Mount(h)
	signIn := func(person string) *servertest.Browser {
		b := &servertest.Browser{Handler: h}
		if w := b.Post(devlogin.LoginPath, url.Values{"person": {person}, "return_to": {"/pages/"}}); w.Code != http.StatusSeeOther {
			t.Fatalf("%s signs in: %d %s", person, w.Code, w.Body)
		}
		return b
	}
	// press opens a page as a person, and presses a button of its form: the answer is 303, to the
	// ticket's card.
	press := func(b *servertest.Browser, page, button string, values map[string]string) string {
		t.Helper()
		w := b.Get(page)
		f, err := servertest.ReadForm(w.Body.Bytes())
		if w.Code != http.StatusOK || err != nil {
			t.Fatalf("the page %s: %d %v", page, w.Code, err)
		}
		for name, v := range values {
			if err := f.Set(name, v); err != nil {
				t.Fatal(err)
			}
		}
		w, err = b.Press(f, button)
		if err != nil {
			t.Fatal(err)
		}
		if w.Code != http.StatusSeeOther {
			t.Fatalf("%s on %s: %d %.500s", button, page, w.Code, w.Body)
		}
		return w.Header().Get("Location")
	}
	card := press(signIn("s1201"), "/pages/requests/purchase/new?lang=en", "button.submit", map[string]string{
		"f.amount": "120000", "f.purpose": "A laptop for the new member of the section",
	})
	id, ok := strings.CutPrefix(card, "/pages/tickets/")
	id, _, _ = strings.Cut(id, "?")
	if !ok {
		t.Fatalf("the request went to %q", card)
	}
	// The things to do after the request: the notice to the manager, which notify.go writes to the
	// log.
	if _, err := srv.RunToDo(t.Context()); err != nil {
		t.Fatal(err)
	}
	if !strings.Contains(log.String(), "msg=notice") || !strings.Contains(log.String(), "s1101@example.com") {
		t.Errorf("no notice to the manager in the log:\n%s", log.String())
	}
	// The notice says the kind by its title in the language notify.go writes in.
	if title, in := srv.Title("purchase", 1, "ja"); in != "ja" || !strings.Contains(log.String(), title) || !strings.Contains(log.String(), "title_lang=ja") {
		t.Errorf("the notice does not say the kind by its title in ja (%q in %q):\n%s", title, in, log.String())
	}
	if again := press(signIn("s1101"), card, "button.approve", nil); again != card {
		t.Errorf("the manager's approval went to %q", again)
	}
	if tk := ticketOf(t, srv, "s1201", id); tk.Status != "in_progress" || tk.Stage == nil || *tk.Stage != "head" {
		t.Fatalf("after the manager: %+v", tk)
	}
	press(signIn("s1001"), card, "button.approve", nil)
	if tk := ticketOf(t, srv, "s1201", id); tk.Status != "approved" {
		t.Errorf("after the head of the department: %+v", tk)
	}
}

// monday is a business day of the office's calendar, at 10:00 in its time.
var monday = time.Date(2026, 11, 16, 10, 0, 0, 0, time.FixedZone("+09:00", 9*60*60))

// newServer makes the server cmd/server makes, with the parts of the project (Parts), a store in
// memory and a clock set to monday: sign says who sends each request, and the log goes to log.
func newServer(t *testing.T, sign server.Authenticator, log *bytes.Buffer) *server.Server {
	t.Helper()
	logger := slog.New(slog.NewTextHandler(log, nil))
	cfg, err := Parts(logger)
	if err != nil {
		t.Fatal(err)
	}
	cfg.Store, cfg.Authenticator, cfg.Clock, cfg.Logger = memstore.New(), sign, servertest.NewClock(monday), logger
	srv, err := server.New(cfg)
	if err != nil {
		t.Fatal(err)
	}
	Started(cfg, srv)
	if err := srv.ImportOrganization(t.Context()); err != nil {
		t.Fatal(err)
	}
	return srv
}

// do does an operation as a person, and answers the reply.
func do(t *testing.T, srv *server.Server, person, op, ticket, body string) server.Reply {
	t.Helper()
	key := person + "." + op + "." + ticket // the operation's idempotency key: visible ASCII
	r, err := srv.Do(t.Context(), server.Call{Operation: op, Person: server.Person{ID: person}, Ticket: ticket, Body: []byte(body), Key: key})
	if err != nil {
		t.Fatalf("%s does %s: %v", person, op, err)
	}
	return r
}

// ticket is what the tests read of a ticket.
type ticket struct {
	ID       string          `json:"id"`
	Status   string          `json:"status"`
	Stage    *string         `json:"stage"`
	Revision json.RawMessage `json:"revision"`
}

// ticketOf reads a ticket as a person who may see it.
func ticketOf(t *testing.T, srv *server.Server, person, id string) ticket {
	t.Helper()
	r := do(t, srv, person, "get_ticket", id, "")
	var b struct {
		Ticket ticket `json:"ticket"`
	}
	if r.Outcome != server.OK || json.Unmarshal(r.Body, &b) != nil {
		t.Fatalf("%s reads %s: %s %s %s", person, id, r.Outcome, r.Problem, r.Body)
	}
	return b.Ticket
}

// gateOrg is a version of an organization of two divisions, for the questions the tests ask the gate
// themselves: a division has departments, a department sections, and the section facilities a unit.
// Each team has one person, in_<the team>. kind gives the name the data uses for the kind of each
// team, from the team's place in the list and the kind the organization declares.
func gateOrg(kind func(place int, declared string) string) *server.OrgVersion {
	teams := []server.Team{
		{ID: "acme", Kind: "company"},
		{ID: "corporate", Kind: "division", Parent: "acme"},
		{ID: "product", Kind: "division", Parent: "acme"},
		{ID: "general_affairs", Kind: "department", Parent: "corporate"},
		{ID: "finance", Kind: "department", Parent: "corporate"},
		{ID: "engineering", Kind: "department", Parent: "product"},
		{ID: "front_desk", Kind: "section", Parent: "general_affairs"},
		{ID: "facilities", Kind: "section", Parent: "general_affairs"},
		{ID: "mail_room", Kind: "unit", Parent: "facilities"},
		{ID: "accounting", Kind: "section", Parent: "finance"},
		{ID: "web", Kind: "section", Parent: "engineering"},
	}
	v := &server.OrgVersion{Day: "2026-04-01"}
	for i, team := range teams {
		team.Name, team.Kind = team.ID, kind(i, team.Kind)
		v.Teams = append(v.Teams, team)
		join(v, "in_"+team.ID, team.ID)
	}
	return v
}

// join adds person to the version, with team their primary team.
func join(v *server.OrgVersion, person, team string) {
	v.People = append(v.People, server.OrgPerson{ID: person, Name: person})
	v.Members = append(v.Members, server.Member{Person: person, Team: team, Primary: true})
}

// asDeclared names each kind of team as the organization declares it.
func asDeclared(_ int, declared string) string { return declared }

// question is what the server asks the gate when person does action at monday, with org the version
// of the organization in effect: of the organization alone for the organization's operations; of
// purchase (version 1, owned by owner, none for "") for those of a request type; for a submit, of the
// person's own new ticket; else of the ticket T-1 of someone else, at its stage head.
func question(org *server.OrgVersion, person server.Person, action, owner string) server.Question {
	q := server.Question{Action: action, Person: person, Now: monday, Org: org}
	switch action {
	case "import_organization", "read_organization_audit":
		return q
	}
	q.Kind, q.Version, q.Owner = "purchase", 1, owner
	switch action {
	case "change_request_type", "read_audit":
	case "submit":
		q.Ticket, q.Requester, q.Requesters = "T-2", person.ID, []string{person.ID}
	default:
		q.Ticket, q.Stage, q.Requester, q.Requesters = "T-1", "head", "the_requester", []string{"the_requester"}
	}
	return q
}

// allows answers whether g allows q. An error of the gate fails the test.
func allows(t *testing.T, g *Gate, q server.Question) bool {
	t.Helper()
	ok, err := g.Allow(t.Context(), q)
	if err != nil {
		t.Fatalf("%s asks %s: %v", q.Person.ID, q.Action, err)
	}
	return ok
}

// HandleTools puts the agents' tools at /mcp of the server st serves: the tools ritsu wrote for the
// kinds of request (requests/mcp/tools.json), over MCP. An agent is the person the server's sign-in
// finds in its requests, as a browser is (serve.Person), and what it does is asked of the gate as
// the pages' and the API's operations are. A request with no one signed in is answered 401.
func HandleTools(st *serve.Stores, log *slog.Logger) {
	st.Handle("/mcp", func(srv *server.Server) (http.Handler, error) {
		tools, err := mcp.New(srv, mcp.Config{Logger: log})
		if err != nil {
			return nil, err
		}
		return tools.Handler(mcp.HTTP{Person: serve.Person})
	})
}

	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}
	addr := l.Addr().String()
	l.Close()
	log := slog.New(slog.NewTextHandler(io.Discard, nil))
	st, err := serve.Open(t.Context(), serve.Flags{Addr: addr, Getenv: func(string) string { return "" }}, log)
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(st.Close)
	HandleTools(st, log)
	cfg, err := Parts(log)
	if err != nil {
		t.Fatal(err)
	}
	cfg.Clock = servertest.NewClock(monday)
	ctx, cancel := context.WithCancel(context.Background())
	served := make(chan error, 1)
	go func() { served <- st.Serve(ctx, cfg, func(srv *server.Server) { Started(cfg, srv) }) }()
	t.Cleanup(func() {
		cancel()
		if err := <-served; err != nil {
			t.Errorf("Serve: %v", err)
		}
	})
	for start := time.Now(); time.Since(start) < 10*time.Second; time.Sleep(20 * time.Millisecond) {
		if c, err := net.Dial("tcp", addr); err == nil {
			c.Close()
			return "http://" + addr + "/mcp"
		}
	}
	t.Fatal("the server does not listen")
	return ""
}

// as sends each request of an agent as a person, in the header X-Person.
type as string

func (p as) RoundTrip(r *http.Request) (*http.Response, error) {
	r = r.Clone(r.Context())
	r.Header.Set("X-Person", string(p))
	return http.DefaultTransport.RoundTrip(r)
}

// callTool calls a tool, and answers the ticket of its result.
func callTool(t *testing.T, agent *sdkmcp.ClientSession, name string, args map[string]any) ticket {
	t.Helper()
	r, err := agent.CallTool(t.Context(), &sdkmcp.CallToolParams{Name: name, Arguments: args})
	if err != nil {
		t.Fatalf("%s: %v", name, err)
	}
	b, err := json.Marshal(r.StructuredContent)
	var result struct {
		Ticket ticket `json:"ticket"`
	}
	if err != nil || r.IsError || json.Unmarshal(b, &result) != nil {
		t.Fatalf("%s: %s", name, b)
	}
	return result.Ticket
}
