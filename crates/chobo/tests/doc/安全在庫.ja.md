# 安全在庫 v1

棚に 3 個を残し、それより下は出荷しない

`chobo doc` が `tests/books/安全在庫.book` から作ったページ。勘定ごとに残高を持ち、残高は入った量から出た量を引いたもの。どの振替も勘定の下限と上限を守り、守れない振替は、その境界に付けた名前で断られて、どの移動も行われない。振替には、すぐに動かすもの（`do`）と、動かす量をまず押さえるもの（`hold`）がある。押さえた分は、あとで確定される（`post`。全部か一部）か、取り消される（`void`）か、有効期限で切れる。

## 勘定

| 勘定 | 分け方 | 単位 | 境界 | 説明 |
|---|---|---|---|---|
| `棚` | `sku` ごと | 個 | 3 以上。下回る振替は `安全在庫割れ` で断る |  |
| `仕入先` | 一つだけ | 個 | 外の勘定。境界は無く、マイナスにもなる |  |
| `客` | 一つだけ | 個 | 外の勘定。境界は無く、マイナスにもなる |  |

## 勘定のあいだの流れ

```mermaid
flowchart LR
    a0["棚(sku)<br>個<br>3 以上（安全在庫割れ）"]
    a1(["仕入先<br>個・外の勘定"])
    a2(["客<br>個・外の勘定"])
    a1 -->|"補充"| a0
    a0 -->|"出荷"| a2
```

四角は勘定で、矢印は振替の移動。角の丸い四角は外の勘定で、境界を持たない。破線の矢印は仮押さえの振替で、まず押さえ、確定したときに動く。

## 振替

### 補充

- 移動: `仕入先` から `棚(sku)` へ `数`。
- キー: `伝票` と `sku` ごとに一回。同じ呼び出しの二度目は何もせず、`done_before` を返す。`数` だけが違う二度目は `key_conflict` で断られる。
- すぐに動かす（`do`）。

| 操作 | 断られうる理由 | いつ |
|---|---|---|
| `補充.do` | `key_conflict` | `伝票` と `sku` が同じで、ほかの引数が違う呼び出しが、前に済んでいる |

<details><summary>断られる例</summary>

#### 補充.do: key_conflict

```text
 1  補充.do(伝票: 伝票-1, sku: sku-2, 数: 1)  通る
 2  補充.do(伝票: 伝票-1, sku: sku-2, 数: 2)  key_conflict で断られる
```

</details>

### 出荷

- 移動: `棚(sku)` から `客` へ `数`。
- キー: `注文` と `sku` ごとに一回。同じ呼び出しの二度目は何もせず、`done_before` を返す。`数` だけが違う二度目は `key_conflict` で断られる。
- すぐに動かす（`do`）。

| 操作 | 断られうる理由 | いつ |
|---|---|---|
| `出荷.do` | `安全在庫割れ` | `棚(sku)` が 3 を下回る |
| `出荷.do` | `key_conflict` | `注文` と `sku` が同じで、ほかの引数が違う呼び出しが、前に済んでいる |
| `出荷.do` | `already_refused` | `注文` と `sku` が同じ呼び出しが、前に境界で断られている。境界で断られたキーは、あとで足りるようになっても通らない |

<details><summary>断られる例</summary>

#### 出荷.do: 安全在庫割れ

```text
 1  出荷.do(注文: 注文-1, sku: sku-2, 数: 1)  安全在庫割れ で断られる（1 つ目の移動が 棚(sku-2) から 1 を取る。確定 0、出ていく仮押さえ 0）
```

#### 出荷.do: key_conflict

```text
 1  補充.do(伝票: 伝票-1, sku: sku-2, 数: 4)  通る
 2  出荷.do(注文: 注文-3, sku: sku-2, 数: 1)  通る
 3  出荷.do(注文: 注文-3, sku: sku-2, 数: 2)  key_conflict で断られる
```

#### 出荷.do: already_refused

```text
 1  出荷.do(注文: 注文-1, sku: sku-2, 数: 1)  安全在庫割れ で断られる（1 つ目の移動が 棚(sku-2) から 1 を取る。確定 0、出ていく仮押さえ 0）
 2  出荷.do(注文: 注文-1, sku: sku-2, 数: 1)  already_refused で断られる
```

</details>

## シナリオ

`chobo scenarios` が帳簿から作ったシナリオ 9 本。境界の手前・ちょうど・超える、同じキーの二度目、仮押さえの終わり方、二つの呼び出し元が同時に最後の一つを取りに来るもの、などがある。どれも参照インタプリタで流し、ステップごとに、そのあとの残高を載せる。残高は確定した量で、仮押さえがあれば括弧の中に書く。
