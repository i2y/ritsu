# ほかの言語と組む

*申請の種類が読むファイルを書く人のためのページです。会社のカレンダー、部門の予算、会社全体の決まり、職務権限表、エージェントの仕事や承認のあとの仕事をするワークフローがそれに当たります。それらを組み合わせるエンジニアも読んでください。*

ringi が意味を与えるのは、フォーム、経路とそれに答える人、チケット、組織の四つだけです。申請に要るほかのものは、どれも ritsu のほかの言語のファイルに書きます。申請はそれを `use` で読み、そのファイルはそれぞれの言語が確かめます。

| 申請が読むもの | 言語 | 何に使うか |
|---|---|---|
| `use calendar 本社(office) from "shared/office.cal"` | koyomi | 期限、催促、日付が数える営業日 |
| `use book 予算(budget) from "shared/budget.book"` | chobo | 出したときに仮押さえし、終わったときに確定するか外す予算や休暇の残り |
| `use gate "shared/company.gate"` | sekisho | 会社全体の決まり。だれがチケットに何をできるか、だれが申請の種類を管理するか |
| `use rule 権限表(authority) from "shared/authority.rule"` | rulec | いくつかの申請が共通して使う表（職務権限表など） |
| `use flow 支払い(pay) from "shared/pay.flow"` | dandori | 承認のあとの仕事、ステップに答えるエージェント、承認者のための要約 |

申請の中に書いたものも、同じように下ろします。経路の表とフォームの計算は rulec の規則に、期限は koyomi の日付のファイルに、各申請のチケットは kaname のモジュールになります。yuen の要求（`shared/expense.req`）は、規程の条文を実現する申請の行を指します。

## `ritsu check` が言語のあいだで確かめること

それぞれの言語は、自分のファイルだけを確かめます。申請と、申請が読むファイルを別の人が書くと、どちらも検査を通るのに、二つがかみ合わないことがあります。`ritsu check` は、その境目も確かめます。

- **ゲートと経路。** サーバーがゲートに尋ねる操作には、どれもゲートが宣言したアクションがあります。経路が見つけた承認者は承認できます。経路が申請者自身に決めさせないところでは、申請者は決められません。決めさせてしまうゲートはエラーになります（E911）。
- **帳簿とチケット。** 申請を出したときの仮押さえは、チケットが開いたままでいられる最も長い期間より長く続きます。仮押さえの引数が読む値は、どの申請者にもあります（E209）。
- **ワークフローとチケット。** 申請がワークフローに渡す値は、ワークフローが受け取る範囲と型に収まります。エージェントのワークフローは、`ok` か、理由を添えた `doubt` で答えます。サーバーの API を通して申請を出すワークフローは、いまの申請の種類にある操作を呼びます（E210）。その呼び出しをする `http` のタスクには `key` を書きます。サーバーはすべての POST に `Idempotency-Key` のヘッダを求め、dandori がタスクのキーをそこに入れます。

例の申請は、読むファイルすべてと一緒に検査して、どの境目も通ります。

```console
$ cd crates/ringi/examples
$ ritsu check expense.ja.ringi purchase.ja.ringi leave.ja.ringi account.ja.ringi --lang ja
ok account.ja.ringi: 申請の種類、フィールド 5 個、ステップ 4 個
…
ritsu check: ファイル 4 個（ringi 4）。どれも検査を通りました（警告 8 件）。言語の境目: 確かめた 38 か所、決められない 0 か所
```

## かみ合わない境目

予算の仮押さえが切れるまでの日数を、365 日から 90 日にします。

```diff
   key request, attempt
-  pending expires after 365 days
+  pending expires after 90 days
```

帳簿は自分の検査を通り、購入の申請も ringi の検査を通ります。`ritsu check purchase.ja.ringi --lang ja` は、二つを一緒に確かめます。

```text
…
エラー[ritsu E209]: purchase.ja.ringi:76:26: `購買稟議` のチケットが仮押さえ `予算.reserve` を確定か取消にする前に、期限が切れることがあります
    76 |   on submitted      hold 予算.reserve(request: ticket.id, attempt: ticket.attempt, dept: requester.department, amount: 合計)  when requester.department is not none
  = 仮押さえは申請を出したときに作り、その `round` が終わるまで開いています。ringi の検査の数え方で、長くて 216 営業日です（一つの `round` が 54 営業日、前のステップへ差し戻すと同じ `round` を歩き直すので 4 回分）。
  = 2030-03-01 に出した申請は、カレンダー `本社` で 216 営業日あとの 2031-01-06 まで開いていることがあり、312 日になります。
  = 仮押さえは、作ってから 90 日で期限が切れます（"crates/ringi/examples/shared/budget.book" の `reserve`）。
  = 期限の切れた仮押さえの確定と取消を、帳簿は `expired` で拒否します。チケットが承認されても、押さえた分はもうありません。
  = 仮押さえの期限を延ばすか（振替の `pending expires after`）、ステップの期限を短くしてください。
ritsu check: ファイル 1 個（ringi 1）。検査を通らないもの 1 個（エラー 1 件、警告 1 件）。言語の境目: 確かめた 8 か所、決められない 0 か所
```

購入は、前のどのステップへも 3 回まで差し戻せ、差し戻しのあいだも仮押さえは続きます。エラーは、仮押さえが開いたままでいられる最も長い期間を、それがいちばん長くなる日から数えて示し、何を変えればよいかも伝えます。`ritsu explain E209` は、このエラーを出す最小のファイルを表示します。E911 と E210 についても同じです。

## 一つのパッケージ

`ritsu gen` は、プロジェクトのすべての言語のコードを、TypeScript、Python、Go、Rust のそれぞれについて一つのパッケージに書きます。規則、日付、帳簿のクライアント、ゲート、ワークフロー、kaname のモジュール、申請のチケットが入ります。サーバーはそれらを一つのプロセスの中で呼ぶので、画面とサーバーには同じ規則が答えます（[生成する物とサーバー](server.md)）。
