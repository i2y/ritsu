# 申請の種類を読む

*申請の種類を管理する人と、申請がだれに回るのか、なぜそうなるのかを知りたい承認者のためのページです。`.ringi` のファイルを読む必要はありません。*

`.ringi` のファイルは、エージェントが書き、ringi が確かめます。人が確かめるのは、それが会社の決まりどおりかどうかです。つまり、各ステップにだれが、だれの申請について、いつまでに答えるかです。ringi はそれを一枚のページに描き、三つの問いに答えます。ある人の申請にだれが答えるか。ファイルが変わると何が変わるか。組織が変わると何が変わるか。

## 申請の種類のページ

`ritsu ringi doc` は、申請の種類を一枚のページに英語か日本語（`--lang ja`）で描きます。ページには、フォーム、各ステップにだれがいつまでに答えるかを示す経路の表、期限と期限を過ぎたときにどうなるか、チケットについて人ができること、主張とそれについて示したこと、シナリオが載ります。例のページは次のとおりです。どれも `ritsu ringi doc <ファイル> --format html --lang ja` が描いたものです。

| 申請の種類 | 部門 | ページ |
|---|---|---|
| 経費、出張、購買 | 経理 | [経費](doc/expense.html) |
| 休暇 | 人事 | [休暇](doc/leave.html) |
| 職務権限表で決まる購入 | 総務 | [購入](doc/purchase.html) |
| 契約の締結 | 法務 | [契約](doc/contract.html) |
| システムの権限 | 情報システム | [権限](doc/account.html) |

いくつかの申請が共通して使うファイルにもページがあります。共通の経路のページには、その経路を使う申請が並びます。組織のページには役職、チームの種類、版が、一覧のページには一覧ごとの行が載ります。[上長による承認の経路](doc/manager_approval.html)、[組織](doc/company.html)、[一覧](doc/masters.html)を見てください。

`--format html` を付けなければ、ページは Markdown で書かれます。リポジトリにそのまま置いて読めます（`ritsu ringi doc leave.ja.ringi --lang ja > leave.md`）。

## ある人の申請にだれが答えるか

`ritsu ringi simulate` は、申請者、フォームの値、日を決めて、各ステップにだれが答えるか、最初のステップの期限がいつかを示します。次は、営業の担当者が 8 日の有給休暇を申請する場合です。

```console
$ cd crates/ringi/examples
$ ritsu ringi simulate leave.ja.ringi --requester e1203 --form 種類=有給,初日=2026-12-21,日数=8 --on 2026-11-16 --lang ja
leave.ja.ringi（2026-11-16、2026-04-01 からの組織）
  計算：復帰日 = 2027-01-06
申請者 e1203（営業担当 3）
  manager  manager：e1101（営業一課長）
           期限は 2026-11-18 の終わり、催促は 2026-11-17 09:00
  head     dept_head：e3101（営業一部長）
           期限は、始まってから 2 営業日目の終わり
```

`--every-requester` を付けると、組織の全員について調べ、同じ承認者に回る人をまとめます。申請をそもそも出せない人と、答える人がいないためにステップがほかへ回る人もわかります。

## 組織が変わると何が変わるか

組織のデータには、変わる日ごとに版があります。`ritsu ringi diff --versions` は、一つの申請の種類を二つの版で読み比べ、承認者が変わる申請者全員と、どう変わるかを挙げます。

```console
$ cd crates/ringi/examples
$ ritsu ringi diff --versions 2026-04-01 2027-04-01 leave.ja.ringi --lang ja
  申請の種類 `休暇`（`crates/ringi/examples/leave.ja.ringi`）を、2026-04-01 に効いている組織（2026-04-01 からの版）と、2027-04-01 に効いている組織（2027-04-01 からの版）で読み比べます。
承認者：
  二つの版にいる 18 人の申請者のうち、4 人の承認者が変わります。
    e1201（営業担当 1）、上長：上長：e1101（営業一課長） → 上長：e3101（営業一部長）
    e1203（営業担当 3）、上長：上長：e1101（営業一課長） → 上長：e3101（営業一部長）
    e9002（弁護士 2）、上長：上長：e9001（法務部長） → 上長：e0102（管理本部長）
    e9002（弁護士 2）、部長：部長：e9001（法務部長） → 部長：legal（法務部）の長が空いています。e0102（管理本部長）へ回ります
    e9003（弁護士 3）、上長：上長：e9001（法務部長） → 上長：e0102（管理本部長）
    e9003（弁護士 3）、部長：部長：e9001（法務部長） → 部長：legal（法務部）の長が空いています。e0102（管理本部長）へ回ります
申請者：
  - 2026-04-01 からの版にだけいる人：e9001（法務部長）、e1203（営業担当 3）［e1201（営業担当 1）が代理で申請］
答える人がいないステップ：
  答える人が見つからない申請者の数が、二つの版で違うステップです。そのときどうなるかは、申請の種類の決まりによります。
    部長、上へ回るか、ほかへ回ります：9 → 10
進行中のチケット：
  承認者が決まったステップは、2027-04-01 のあともそのまま進みます。2027-04-01 以降に始まるステップは、2027-04-01 からの版で承認者が決まります。待っている承認者が組織からいなくなったチケットは、管理する人が引き継ぎます。期限を過ぎて上へ回るときは、そのとき効いている版で回る先が決まります。
```

2027-04-01 から、営業一課の担当者は営業一部長に直接つき、法務部には長がいなくなるので、弁護士のステップは本部長へ回ります。すでに進んでいるチケットがどうなるかは、最後に書いてあります。

## ファイルが変わると何が変わるか

`ritsu ringi diff <古いファイル> <新しいファイル>` は、申請の種類の二つの版を比べます。どの申請がほかのステップに回るようになるか、組織の版ごとにだれの承認者が変わるかを示します。次は、部長の承認を 6 営業日からではなく 4 営業日からにした休暇です。

```diff
-request 休暇(leave_ja) v1 "休暇の申請"
+request 休暇(leave_ja) v2 "休暇の申請"
…
-route 標準(long: 日数 > 5)
+route 標準(long: 日数 > 3)
```

書き換えたものを `leave.ja.v2.ringi` として隣に置くと、`ritsu ringi diff leave.ja.ringi leave.ja.v2.ringi --lang ja` は次のように言います。

```text
  申請の種類 `休暇`（v1 → v2）：`crates/ringi/examples/leave.ja.ringi` → `crates/ringi/examples/leave.ja.v2.ringi`
経路：
  「営業日の日数」が4から5までの申請：ステップ「部長」（部長）が来るようになります。
  2026-04-01 からの組織で、20 人のうち 20 人の承認者が変わります。
    e0101（営業本部長）、部長：来ません → 部長：種類 `department` のチームが、申請者の上にありません。e0001（社長（架空））へ回ります
…
  ほかに 8 件あります。すべては `--format json` で出ます。
  ほかの申請は、どれも同じステップに進みます。
進行中のチケット：
  チケットは、出したときの申請の種類の版で終わります。版 1 で出したチケットは版 1 のとおりに終わり、ここに並べた変更は、版 2 で出す申請に効きます。
```

`ritsu ringi diff --format html` が描くページは、同じことを人が読む形で伝えます。`ritsu mod diff` は、申請の種類を集めたモジュールに新しい版が出たとき、申請の種類ごとに同じことを言います。

## 一件のチケットが長くてどれだけかかるか

`ritsu ringi doc --longest` は、いちばん長くかかるチケットを描きます。どのステップも期限の最後の日まで遅れ、差し戻しを上限まで受け、出し直しもそのたび最後の日にした場合で、それが何営業日になるかを示します。検査は、それが主張 `every ticket ends within` に収まることを確かめます。
