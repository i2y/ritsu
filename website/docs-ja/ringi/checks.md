# 検査が保証すること

*申請の種類を頼りにする人のためのページです。書くエージェントとエンジニア、使い始める前に中身を認める管理者が読みます。*

`ritsu ringi check` は、申請の種類を三つの面から確かめます。ringi 自身が知っていること（フォーム、経路、チケット、組織）、ringi が下ろした先の言語が知っていること（表と条件は rulec、期限は koyomi）、そして組織のデータです。データは版ごと、人ごとに確かめます。`ritsu check` は、プロジェクトのすべての `.ringi` に同じ検査を、ほかの言語のファイルと一緒に回します。このページでは、例について検査が何を言うか、例を書き換えると何を言うかを見せます。

## ringi が自分で確かめること

- **語と名前。** 置き場所の違う語、二度宣言した名前や宣言していない名前、読めない `use`、そのファイルの種類に書けないブロックを見つけます。
- **フォーム。** 数、金額、日付には範囲が、文字列には長さの上限が要ります（E101、E102）。計算で決まるフィールドの範囲は、計算が取りうる値と合っていなければなりません（E103）。金額はどう丸めるかを書きます（E104）。必須のフィールドは隠せません（E105）。条件が読めるのは、それより前に入れるフィールドだけです（E106）。
- **経路。** 定足数は、数える承認者の数を超えられません（E304）。選ぶ人は、それを選べるステップから来なければなりません（E305）。共通の経路には、経路が受け取るものを渡します（E307）。どこかで名前を挙げたステップは、経路にあるものでなければなりません（E308）。
- **チケット。** 主張に書けば、どの催促も期限より前に来ること（E403）と、どのチケットも書いた日数のうちに終わること（E401）を確かめます。帳簿の仮押さえは、どの終わり方でも確定するか外されます（E405）。仮押さえのキーには出し直しの回を含めるので、出し直した申請はもう一度押さえます（E408）。

## 下ろした先の言語が確かめること

ringi は、表、条件、計算、期限に独自の意味を与えません。それぞれを意味を持つ言語のファイルとしてメモリの中で書き、その言語に確かめさせます。経路の表とフォームの計算は rulec の規則になり、期限は koyomi の日付のファイルになります。見つかったことは、ringi の言葉で、ringi のファイルの行について言い直します。

- フォームが取りうるどの値も、経路のちょうど一つの行に当たります（E301、E302）。どの値も当たらない行はありません（E303）。
- 主張はフォームのどの値についても成り立ちます。成り立たなければ、成り立たない値を示します（E306）。
- 例は、書いたとおりの答えになります（E601）。

## 組織のデータでわかること

組織のデータを読むと、検査は組織の版ごとに、申請を出せる人ひとりひとりについて、各ステップにだれが答えるかを求めます。そこから次のことがわかります。

- データそのもの。サーバーと同じ厳しさで読み、足りない列、`organization.json` の知らないキー、上限を越える値、形の違う行を、その行で言います（E501）。
- 答える人がいないのに、そのときどうするかを経路が書いていないステップ（E502）と、書いたとおりに上へ回るか飛ばされるステップ（W502）。
- 一部の申請者では届かない定足数（E504）、一件のチケットの二つのステップに答える一人の人（W506）、期限を過ぎても上へ回す先の無いステップ（W507）。
- 上へ回す元として名前を挙げた人が、ある版にいないこと（E503）。
- 申請を使える日の範囲。組織の最初の版から、カレンダー、組織、一覧が扱う日の終わりまでです。

契約の審査（`contract.ja.ringi`）は、いまの組織では検査を通り、2027-04-01 から効く組織では通りません。その日から法務部長がデータにいなくなり、法務部には申請者のほかに弁護士が一人しか残りません。ところが、500 万円を超える契約は弁護士二人の承認を求めます。

```console
$ cd crates/ringi/examples
$ ritsu ringi check contract.ja.ringi --lang ja
エラー[E504]: contract.ja.ringi:31:17: 2027-04-01 からの組織では、ステップ `二人目` が 2 人の承認に届かない申請者がいます
    31 |   二人目(second)   at least 2 of 法務  when 金額 > 5_000_000円
  = `法務` に、申請者のほかの人が 1 人しかいません。
  = 申請者 2 人: e9002（弁護士 2）、e9003（弁護士 3）。
  = チームに人を足すか、議決の数を変えてください。
警告[W506]: contract.ja.ringi:33:17: 2026-04-01 からの組織では、一つのチケットの二つのステップに同じ人が当たります
    33 |   法務部長(counsel) 部長              when 金額 > 10_000_000円
  = ステップ `上長` の決め方は `上長`、ステップ `法務部長` の決め方は `部長` で、同じ人に当たります。
  = e9001（法務部長）が両方に当たる申請者 2 人: e9002（弁護士 2）、e9003（弁護士 3）。
  = 一度の承認でよいなら、`ticket` に `same approver approves once, at the last stage` と書いてください。`上長` は、あいだのステップのあとの `法務部長` の承認を待ちます。
  = 一人が二度確かめても、二人が確かめたことにはなりません。どちらかのステップの承認者の決め方を変えるか、そのままでよいかを確かめてください。
エラー[E503]: contract.ja.ringi:41:3: 2027-04-01 からの組織では、`部長` が指す人かチームがありません
    41 |   部長(counsel)     = person "e9001"
  = `部長` が指す e9001 は、2027-04-01 からの組織にいません。
  = ステップ `法務部長` は `when empty escalate` ですが、組織にいない人やチームからは上へ回せません（`then` のあとに書いたことが効くのは、上に人がいないときだけです）。
  = ID を直すか、その版のデータに人かチームを足してください。
```

変わったのはファイルではなく組織です。検査はデータのすべての版を読むので、チケットが止まる日より前のいま、このエラーを伝えます。ある日に有効な版だけで読むと（`--at`）、契約の審査は検査を通ります。`ok` の行の下には、データから求めたことが並びます。

```console
$ cd crates/ringi/examples
$ ritsu ringi check contract.ja.ringi --at 2026-11-16 --lang ja
警告[W506]: contract.ja.ringi:33:17: 2026-04-01 からの組織では、一つのチケットの二つのステップに同じ人が当たります
    33 |   法務部長(counsel) 部長              when 金額 > 10_000_000円
  = ステップ `上長` の決め方は `上長`、ステップ `法務部長` の決め方は `部長` で、同じ人に当たります。
  = e9001（法務部長）が両方に当たる申請者 2 人: e9002（弁護士 2）、e9003（弁護士 3）。
  = 一度の承認でよいなら、`ticket` に `same approver approves once, at the last stage` と書いてください。`上長` は、あいだのステップのあとの `法務部長` の承認を待ちます。
  = 一人が二度確かめても、二人が確かめたことにはなりません。どちらかのステップの承認者の決め方を変えるか、そのままでよいかを確かめてください。
ok contract.ja.ringi: 申請の種類、フィールド 8 個、ステップ 7 個
  2026-04-01 から使えます: 組織 `shared/company.ringi` の最初の版（データ `../org`）
  終わり無く使えます: 読むデータに終わりがありません
  長くても 192 営業日で終わります（ステップに 4 × 38、申請者のもとで 3 × 10、保留に 10）
  組織の形で、ステップ（`上長`、`法務部長`）がほかへ回るか飛ばされる申請者: 2026-04-01 からの組織の 24 人のうち 2 人
  組織の形で、期限を過ぎたステップ（`上長`）を上へ回せない申請者: 2026-04-01 からの組織の 24 人のうち 6 人
  だれの申請の、どのステップがどこへ回るか: `ritsu ringi simulate contract.ja.ringi --every-requester`
```

## シナリオ

シナリオは、参照インタプリタで一行ずつ、各行に書いた時刻に回します。行に書いたステップや状態にチケットがならなければ、検査は落ちます（E602）。その時点のチケットが受け付けないイベントを書いた行も落ちます（E603）。

## 書き換えたときに検査が言うこと

経費の申請の表から、3 万円を超え 10 万円以下の出張の行を消します。

```diff
 | 出張 | <=30_000円               |                    |             |                 | エージェント決裁 |
-| 出張 | >30_000円 <=100_000円    |                    |             |                 | 上長           |
 | 出張 | >100_000円               |                    | 上長        |                 | 部長           |
```

`ritsu ringi check expense.ja.ringi --lang ja` の出力です。

```text
エラー[E301]: expense.ja.ringi:29:1: 経路の表に当てはまらない申請があります
    29 | route
  = どの行にも当てはまらない申請の範囲: 種別が 出張、合計が 30_001円 から 100_000円
  = 当てはまる行の無い申請: 種別 = 出張、合計 = 30_001円
  = 表に次の行を足し、`?` に、そのステップに答える承認者（`who` の名前）を書いてください（そのステップを飛ばす申請なら空のセル）: | 出張 | >30_000円 <=100_000円 | ? | ? | ? | ? |
  = セルは、表がすでに書いている区切りと範囲の端だけで切ってあるので、このまま足せば穴は埋まります。行の途中で承認者が変わるなら、そこで行を分けてください。
  = この誤りから出た診断が、ほかに 4 件あります（例と主張が、この誤りのために成り立たないなど）。この誤りを直してから、もう一度確かめてください。
…
```

どの行にも当たらない出張を rulec が見つけ、ringi はそれを、表に足す行として表の言葉で示します。

エージェントが決裁するのは 3 万円までという主張を、2 万円と書き間違えます。

```diff
-  エージェントが決裁するのは3万円まで : 決裁 is エージェント決裁 only when 合計 <= 30_000円
+  エージェントが決裁するのは3万円まで : 決裁 is エージェント決裁 only when 合計 <= 20_000円
```

`ritsu ringi check expense.ja.ringi --lang ja` の出力です。

```text
…
エラー[E306]: expense.ja.ringi:81:3: 主張 エージェントが決裁するのは3万円まで が成り立ちません。ステップ 決裁 が `エージェント決裁` になる申請が、条件の外にあります
    81 |   エージェントが決裁するのは3万円まで : 決裁 is エージェント決裁 only when 合計 <= 20_000円
  = その申請: 種別 = 出張、合計 = 20_001円
  = 経路を直すか、条件を直してください。
```

催促を、期限と同じ日にします。

```diff
   due in 3 business days at end of day
-  remind after 2 business days at 09:00
+  remind after 3 business days at 09:00
   when late escalate by 一段上, then expire
```

`ritsu ringi check expense.ja.ringi --lang ja` の出力です。

```text
…
エラー[E403]: expense.ja.ringi:83:1: 期限より前に来ない催促があります
    83 |   催促は期限より前                   : every stage reminds before it is due
  = koyomi の言い方: 条件「催促は期限より前」が、started 146,097 日のうち 146,097 日で成り立ちません
  = 成り立たない日: 2026-04-01〜2426-03-31
  = いちばん外れるのは started 2026-04-01 のときで、remind 2026-04-06 は due と同じ日
  = 催促の日数を期限より短くしてください。
```

どの診断にも、[診断の一覧](https://github.com/i2y/ritsu/blob/main/crates/ringi/docs/codes.ja.md)にページがあり、それを出す最小のファイルが載っています。`ritsu ringi explain <コード>` でも同じものを表示できます。

## 検査が言わないこと

- **データが会社の実際の姿か。** 検査は、渡された組織のデータをそのまま読みます。だれがどこに属し、だれの上長がだれかは、データに書いてあるとおりです。
- **経路が会社の決まりどおりか。** 検査を通った経路には抜けが無く、一つの申請に二つの行が当たることもありません。けれども、それが規程の求める経路かどうかは、人が[人のためのページ](reading.md)で読んで確かめてください。
- **サーバーが何をするか。** 検査が確かめるのは、申請の種類と、そこから作るコードです。チケットを動かすサーバーは、ベクタで同じ答えを返すことを確かめます（[生成する物とサーバー](server.md)）。
